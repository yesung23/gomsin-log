# Design v2.1 시각 파일럿 가이드

- 작성일: 2026-08-09
- 대상 브랜치: `design/v2.1-editorial-density`
- 목적: `DESIGN_V2.md` `시각 수용 기준`의 **마지막 미검증 항목 1개**를 판정한다

## 1. 이 파일럿이 답해야 하는 질문 하나

> 대표 사용자 평가에서 “정돈됐다·젊다·한눈에 보인다”가 반복되고
> “시니어 모드 같다·업무 앱 같다·AI 템플릿 같다”는 반복 의견이 없어야 한다.

나머지 수용 기준 5개는 2026-08-09에 코드와 렌더로 판정이 끝났다(`DESIGN_V2.md`
`시각 수용 기준 대조 결과`). 이 항목만 사람의 눈이 필요하다.

**이것은 기능 테스트가 아니다.** 버그 리포트를 모으는 자리가 아니고, "이 화면이 어떻게
읽히는가"를 재는 자리다. 참가자에게 과제를 주면 과제 수행에 집중해서 첫인상이 사라진다.

`docs/PILOT_GUIDE.md`(기능·프라이버시 운영)와 `docs/PWA_PILOT_GUIDE.md`(설치 절차)는
각각 다른 목적의 문서다. 이 문서는 그 둘을 대체하지 않는다.

## 2. 참가자

최소 5명, 권장 8명. 아래 구성을 지킨다.

| 조건 | 인원 | 이유 |
| --- | --- | --- |
| 곰신 (기다리는 쪽) | 3명 이상 | 곰신 홈이 판정 대상 |
| 군화 또는 전역자 | 2명 이상 | 군화 홈의 `통화 전 60초`가 이 앱의 핵심 |
| 이 앱을 처음 보는 사람 | 전원 | 첫인상이 측정 대상이므로 기존 사용자는 부적합 |
| 20대 | 5명 이상 | “시니어 모드 같다”는 지적이 나온 연령대가 판정 기준 |

개발·디자인 직군은 넣지 않는다. 그들은 밀도와 위계를 언어로 설명해버려서, 우리가 재려는
"그냥 어떻게 느껴지는가"가 나오지 않는다.

## 3. 준비물

두 방식 중 하나. **A를 권장한다.**

### A. 실제 기기에서 앱을 본다

```
node node_modules/vite/bin/vite.js build
node node_modules/vite/bin/vite.js preview --port 4173 --host
```

참가자 폰을 같은 와이파이에 붙이고 출력된 주소로 접속한다. 설치까지 체험시킬 필요는
없다(설치 절차는 `PWA_PILOT_GUIDE.md`의 범위다).

### B. 캡처 이미지를 순서대로 보여준다

원격 참가자용. 아래로 152 프레임을 만들고 **390px / 라이트** 세트만 쓴다.

```
node node_modules/vite/bin/vite.js build --config design-preview/vite.config.ts --outDir <dist>
node design-preview/capture.mjs <dist> <outDir>
```

B는 스크롤과 터치 감각이 빠지므로 “한눈에 보인다” 판정에 불리하다. A가 가능하면 A로 한다.

## 4. 진행 순서

한 사람당 15분. 순서를 바꾸지 않는다. 첫 화면의 첫인상이 가장 중요한 데이터이고, 한 번
쓰면 두 번 다시 얻을 수 없다.

### 1단계 — 5초 노출 (2분)

역할에 맞는 홈 화면(`gomsin-home` 또는 `soldier-home`)을 **5초만** 보여주고 가린다.

> "방금 본 화면, 어떤 앱 같았어요?"
> "무엇이 가장 먼저 눈에 들어왔어요?"

5초는 위계를 재는 시간이다. 이때 D-Day나 배지를 먼저 말하면 위계가 잘못 잡힌 것이고,
상대의 사진·문장·기록 버튼을 말하면 의도대로 잡힌 것이다.

### 2단계 — 자유 탐색 (7분)

과제를 주지 말고 그냥 만지게 한다. 침묵이 흘러도 개입하지 않는다.
생각을 소리 내어 말해달라고만 부탁한다.

진행자는 **말을 유도하지 않는다.** 특히 “정돈돼 보이죠?” 같은 확인 질문은 이 파일럿의
데이터를 통째로 무효로 만든다.

### 3단계 — 표현 선택 (3분)

아래 12개를 **무작위 순서로 섞어** 보여주고 해당하는 것을 모두 고르게 한다.
긍정 6개와 부정 6개가 섞여 있다는 사실은 알리지 않는다.

```
정돈됐다      복잡하다      젊다        나이 들어 보인다
한눈에 보인다   답답하다      따뜻하다     업무용 앱 같다
믿음이 간다    시니어 모드 같다  내 것 같다   AI가 만든 것 같다
```

### 4단계 — 두 화면 비교 (3분)

기록 탭(`record-timeline`)을 보여주고 묻는다.

> "여기서 누가 쓴 글인지 어떻게 구분했어요?"

색을 말하지 않고 구분했다면 WCAG 1.4.1 의도가 살아 있는 것이다. 색만 말하면
마커 모양(채운 점 / 빈 링)을 못 본 것이므로 기록한다.

## 5. 판정 기준

참가자 8명 기준. 5명이면 비율로 환산한다.

| 결과 | 조건 |
| --- | --- |
| **합격** | 긍정 표현이 1인당 평균 2개 이상이고, 부정 표현 중 어느 하나도 3명 이상에게 선택되지 않음 |
| **조건부** | 부정 표현 1개가 3~4명에게 선택됨 → 해당 항목만 좁혀서 재작업 |
| **불합격** | 부정 표현 어느 하나가 5명 이상, 또는 `시니어 모드 같다` / `업무용 앱 같다` / `AI가 만든 것 같다`가 3명 이상 |

마지막 세 표현은 이 개정을 시작한 이유 그 자체다. 다른 부정 표현보다 낮은 임계값을 쓰는
것이 의도다.

### 판정 시 하지 말 것

- 개별 의견 하나로 디자인을 바꾸지 않는다. **반복**이 기준이다.
- "이 카드를 더 크게" 같은 해결책 제안은 그대로 반영하지 않는다. 무엇이 불편했는지를
  받아 적고, 해결은 `DESIGN_V2.md`의 원칙 안에서 다시 설계한다.
- 부정 의견이 나왔다고 밀도를 되돌리지 않는다. 밀도를 높인 것이 이 개정이고,
  되돌리면 시작점으로 돌아간다.

## 6. 기록 양식

참가자당 한 장. 원문 표현을 그대로 적는다. 요약하면 반복 여부를 셀 수 없다.

```
참가자:            역할: 곰신 / 군화        나이대:
방식: A(실기기) / B(캡처)

[1단계] 5초 후 첫 마디 (그대로 인용):
[1단계] 가장 먼저 본 것:

[2단계] 탐색 중 발화 (그대로 인용, 3개 이상):
[2단계] 막힌 지점:

[3단계] 선택한 표현:

[4단계] 작성자 구분 방법 (색을 말했는가: 예 / 아니오):

진행자 메모:
```

## 7. 이 파일럿의 범위가 아닌 것

- 기능·프라이버시·권한 검증 → `docs/PILOT_GUIDE.md`
- 설치·PWA 동작 → `docs/PWA_PILOT_GUIDE.md`
- 오버플로·대비·행간 → 코드로 이미 판정됨. 여기서 다시 묻지 않는다
- 설정 화면 두 버튼의 포커스 링 미표시 → 원인 미확정 상태이며 별도 PR 대상
