# 곰신로그 종단간 암호화 도입 결정서

최종 검토: 2026-08-09

## 결론

현재 운영 버전은 TLS, Supabase RLS, 비공개 Storage와 서명 URL을 사용하지만
종단간 암호화(E2EE)는 아니다. 서버가 보관하는 암호키로 데이터를 암호화하는 방식도
운영자가 복호화할 수 있으므로 E2EE라고 부르지 않는다.

출시를 서두르기 위해 임의의 공통 비밀번호나 6자리 초대 코드에서 키를 만드는 방식을
넣지 않는다. 초대 코드는 엔트로피가 너무 낮아 오프라인 대입 공격을 막을 수 없고,
복구 설계가 없는 클라이언트 암호화는 휴대폰 분실·재설치 때 연인의 전체 기록을 영구
유실시킬 수 있다.

## 출시 전에 유지할 보안 경계

- HTTPS 전송, 최소 권한 RLS, 비공개 파일 버킷, 단기 서명 URL을 유지한다.
- 사진 EXIF 위치정보를 제거하고, 여행 지도 캡처 OCR은 기기 안에서만 수행한다.
- 서비스와 개인정보 처리방침 어디에서도 “운영자도 볼 수 없음” 또는 “E2EE”라고
  표현하지 않는다.
- 운영자 계정은 MFA를 사용하고 Supabase `service_role` 키를 브라우저·Vercel의
  `VITE_` 환경변수·Git에 넣지 않는다.

## 권장 E2EE 구조

1. 각 커플 공간마다 무작위 256비트 콘텐츠 키(CMK)를 기기에서 생성한다.
2. 각 기기는 Web Crypto의 ECDH P-256 키 쌍을 만들고 개인키는 추출 불가능한
   `CryptoKey`로 기기 저장소에 둔다. 네이티브 앱에서는 Keychain/Android Keystore로
   감싼다.
3. CMK는 각 등록 기기의 공개키로부터 만든 키 암호화 키(KEK)로 다시 암호화한
   envelope만 서버에 저장한다. 서버에는 평문 CMK나 기기 개인키를 보내지 않는다.
4. 새 기기는 기존 기기의 QR 승인 또는 별도 복구키로만 등록한다. 두 방법 모두 없으면
   운영자도 복구하지 못한다는 경고를 확인받는다.
5. 본문과 민감 필드에는 AES-256-GCM을 사용하고, 매 객체마다 새 96비트 nonce와
   인증된 부가 데이터(`couple_id`, 객체 종류, 객체 id, key version)를 사용한다.
6. 사진·영상·음성은 압축·EXIF 제거 후 기기에서 암호화해 업로드한다. 썸네일도 별도
   키와 nonce로 암호화하고 평문 임시 파일을 남기지 않는다.

## 암호화 대상과 남는 메타데이터

- 암호화: 기록 본문, 감정 상세, 메모, 일정·여행 제목/주소/링크/준비물, 복무 메모,
  사진·영상·음성 바이트와 파일명.
- 서버 검색·정렬을 위해 평문으로 남길 수 있는 최소 메타데이터: 객체 id, 작성자 id,
  커플 id, 생성 시각, 날짜 버킷, 공개 범위, 삭제 상태, 암호화 버전, ciphertext 길이.
- 날짜 자체도 민감하다고 선택한 사용자를 위해 장기적으로 encrypted date index를
  제공하되, 이 경우 서버 정렬·캘린더 쿼리 기능이 제한됨을 알린다.

## AI 기능과의 경계

서버가 자동으로 본문을 복호화해 감정을 분석하면 E2EE가 아니다. 감정 추론은 기본적으로
기기 안에서 실행한다. 외부 AI API를 쓰는 프리미엄 기능은 사용자가 선택한 콘텐츠만
일회성으로 복호화해 해당 업체로 전송하고, 전송 항목·목적·보관기간을 별도 동의 화면에
표시해야 한다. 이 전송 구간은 두 사용자 사이 E2EE 보호 범위를 벗어난다.

## 마이그레이션 순서

1. 암호화 버전과 ciphertext/envelope 테이블을 추가하되 기존 평문 읽기를 유지한다.
2. 내부 테스트 커플로 다기기 등록, 키 회전, 연결 해제, 계정 삭제, 오프라인 outbox,
   미디어 재생과 복구키 분실을 검증한다.
3. 사용자가 복구키를 확인한 뒤에만 신규 데이터를 E2EE로 저장한다.
4. 기존 평문은 두 기기 중 하나가 로그인한 상태에서 읽고 암호화해 다시 쓰며, 성공
   확인 전 원본을 삭제하지 않는다.
5. 두 계정 모두 암호문을 정상 해독한 것을 확인한 뒤 평문 열과 임시 파일을 제거한다.
6. 외부 보안 검토와 복구 훈련을 통과한 뒤에만 UI와 정책에 E2EE라고 표시한다.

## 출시 게이트

- 잘못된 키·nonce 재사용·부분 업로드·중간 연결 해제에서 데이터가 손상되지 않는다.
- 기존/신규 두 계정, 두 브라우저, 재설치 기기에서 같은 기록을 복호화한다.
- 한 기기를 철회하면 이후 키 버전에 접근할 수 없다.
- 서버 DB와 Storage를 통째로 받은 공격자가 콘텐츠 평문을 얻지 못한다.
- 복구키가 없는 경우 운영자도 복구할 수 없음을 제품 문구와 고객지원 절차가 일치시킨다.

이 조건을 충족하기 전에는 부분 암호화를 E2EE로 출시하지 않는다.
