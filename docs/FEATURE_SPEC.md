# 곰신로그 전체 기능 명세서

- 기준: 현재 구현 + 검증 예정 항목
- 상태 표기: `구현`은 현재 코드에 존재, `검증`은 실제 두 계정 확인 필요, `후보`는 아직 제품 결정 전
- 시각 기준: `docs/design-references/clean-couple-ui-reference.jpg`의 밀도·리스트·타임라인 문법과 `DESIGN_V2.md` 2026-08-08 개정

## 1. 공통 구조

| 영역 | 경로 | 대상 | 목적 | 상태 |
| --- | --- | --- | --- | --- |
| 인증 콜백 | `/auth/callback` | 모두 | Google 로그인 완료와 안전한 세션 복구 | 구현 |
| 온보딩 | `/onboarding` | 신규 사용자 | 역할·복무 정보·커플 연결 설정 | 구현 |
| 홈 | `/`, `/home` | 모두 | 역할별 가장 중요한 다음 행동 | 구현 |
| 기록 | `/record` | 모두 | 공유된 하루와 추억 탐색 | 구현 |
| 일정 | `/schedule` | 모두 | 일정과 공동 할 일 관리 | 구현 |
| 여행 | `/trips`, `/trips/:id` | 모두 | 여행별 장소·순서·준비 관리 | 구현 |
| 우리 | `/us` | 모두 | 관계·기념일·다가오는 여행 보기 | 구현 |
| 복무 | `/service` | 모두 | 복무 진행·D-Day·휴가/면회 | 구현 |
| 마이/설정 | `/my`, `/settings` | 모두 | 프로필·연결·데이터·계정 관리 | 구현 |

하단 탭은 홈·기록·일정·우리·마이다. 일정 안에서 일정/여행을 전환한다. `/service`와 `/settings`는 마이와 설정 바로가기로 접근한다.

## 2. 인증과 온보딩

### 입력과 단계

1. Google 로그인
2. 역할 선택: 곰신 또는 군화
3. 닉네임 입력
4. 군 복무 상태: 입대 예정·복무 중·전역 예정·전역
5. 군종: 육군·해군·공군·해병대·상근예비역·사회복무·기타
6. 입대일·전역일과 기념일 입력
7. 커플 공간 새로 만들기 또는 6자리 초대 코드로 참가

### 규칙

- 인증 콜백은 PKCE 처리 중 세션 확인 경쟁을 견딘다.
- 초대 코드는 유효기간과 사용 여부를 검사한다.
- 커플 연결이 끝나지 않아도 개인 영역은 안내 상태로 진입할 수 있다.
- 계정 삭제 대기 상태면 일반 화면보다 복구/완료 안내를 우선한다.

## 3. 홈과 위젯

### 공통

- 위젯 추가·제거·드래그 순서 변경과 키보드 조작을 지원한다.
- 허용되지 않은 역할의 위젯과 사라진 위젯 ID는 렌더링하지 않는다.
- 커플 연결 상태 변경은 배너로 알린다.
- 홈은 큰 카드의 모음이 아니라 역할별 핵심 행동과 실제 기록의 입구다. 390×844 첫 화면에서 주요 행동과 실제 콘텐츠 일부가 함께 보여야 한다.

### 곰신 기본 홈

- 컴팩트한 기록 시작 영역: 글·사진/영상·음성·반응
- 오늘 둘이 남긴 실제 기록
- 축소형 전역 D-Day

기록 시작 영역은 빈 본문 입력·감정·공개 범위·통화 표시를 한꺼번에 펼치지 않는다. 사용자가 기록 방식을 선택하면 기존 초안 보존 계약을 유지한 작성 흐름으로 이어진다.

### 군화 기본 홈

- 통화 전 60초(고정)
- 상대방의 오늘 타임라인
- 축소형 전역 D-Day

`통화 전 60초`는 판단 화면, `상대방의 오늘`은 근거 화면이다. 브리핑은 텍스트 발췌와 우선순위만, 타임라인은 실제 사진·음성·사용자 원문만 중심에 둔다. 390×844에서는 브리핑 확인 버튼과 타임라인 일부가 함께 보여야 한다.

### 추가 가능한 위젯

상대방 마음 흐름, 오늘의 요약, 다정한 한마디, 오늘의 기록, 기록 모아보기, 다가오는 일정, 복무 진행률, 다음 기념일, 다음 휴가·면회, 추억 다시보기, 오늘의 컨디션을 역할 허용 범위에 따라 제공한다. 군화 홈에서 내린 파생 위젯은 삭제하지 않고 브리핑 `더 보기`, 기록 탭, 위젯 추가에서 접근한다.

## 4. 오늘의 기록

### 입력

- 글, 사진, 영상, 음성, 반응(좋았어·이런 일이·힘들었어·네 생각났어)
- 감정 후보 확인·수정·삭제
- `우리에게 공유` 또는 `나만 보기`
- `통화 때 꼭 얘기`

홈에서는 기록 유형을 먼저 고르는 컴팩트한 런처만 보여준다. 시각적 타일은 과도하게 크거나 서로 다른 강한 색을 쓰지 않으며, 실제 터치 영역은 최소 44px을 유지한다.

### 동작

- 탭을 이동해도 작성 중 초안을 보존한다.
- 오프라인이면 발송함에 보관하고 연결 회복 후 전송한다.
- 업로드 실패 시 본문과 실패 파일을 잃지 않고 재시도한다.
- 중복 제출과 허용되지 않은 파일을 막는다.
- 비공개 기록은 상대방의 모든 화면과 브리핑 후보에서 제외한다.

## 5. 기록 모아보기

- 월 달력과 선택 날짜 목록
- 전체·사진·영상·음성·글 필터
- 여행 기간으로 들어오면 해당 기간만 표시
- 곰신/군화 기록을 색·위치·작성자 텍스트로 구분
- 기본 목록은 날짜 제목 아래 `시간 → 미디어 썸네일 → 작성자·원문·상태`가 이어지는 컴팩트 타임라인이다.
- 사용자 원문은 최대 2~3줄로 먼저 보여주고, 상세에서 전체를 읽는다. 앱이 만든 제목이나 요약은 개별 기록의 제목처럼 표시하지 않는다.
- 사진·영상은 실제 비율을 해치지 않는 썸네일, 음성은 재생 상태와 길이가 보이는 행으로 표시한다.
- 개별 기록마다 큰 둥근 카드를 만들지 않고 여백이나 얇은 구분선으로 항목을 나눈다.
- 반응, `통화 때 꼭 얘기`, `나만 보기`는 작고 읽을 수 있는 라벨로 표시하며 콘텐츠보다 시각적으로 앞서지 않는다.
- 상세에서 미디어 재생, 본문·감정 수정, 첨부 추가/삭제, 본인 기록 삭제
- 브리핑 원문 이동 시 해당 기록으로 스크롤하고 강조
- 로딩·빈 상태·권한 오류·동기화 지연을 구분

## 6. 통화 전 60초

### 대상과 데이터

- 활성 커플에 연결된 군화에게만 홈 최상단 고정 노출
- 최근 7일 또는 마지막 확인점 이후의 공유 기록만 사용
- 비공개 기록은 어떤 경우에도 사용하지 않음

### 우선순위

1. `통화 때 꼭 얘기`
2. 힘들었어
3. 네 생각났어
4. 이런 일이
5. 질문 단서가 있는 기록
6. 좋았어
7. 최신 기록

최대 3개만 보여주며 날짜·시간·작성자·실제 발췌·원문 이동을 제공한다. 먼저 살펴볼 마음과 첫 질문은 실제 공유 기록에 근거하며 진단이나 단정 표현을 쓰지 않는다.

`여기까지 확인`은 현재 포함된 기록 ID와 시각을 기기·사용자·커플 단위로 저장한다. 저장 실패 시 기존 목록과 확인점을 유지하고 재시도할 수 있게 한다.

## 7. 일정과 공동 할 일

### 일정

- 유형: 기념일·면회·휴가·데이트·여행·기타
- 제목, 날짜, 시작/종료 시각, 설명, 공유 범위, `통화 때 꼭 얘기`
- 월 이동, 날짜 선택, 다가오는 일정 확인
- 작성자 권한에 따른 수정·삭제

### 공동 할 일

- 빠른 제목 입력, 마감 날짜·시각, 담당자(나/함께)
- 완료/미완료 토글, 소유자 삭제
- 선택 날짜에 연결해 일정과 한눈에 확인

오프라인에서는 마지막 데이터를 볼 수 있으나 계획 변경은 읽기 전용으로 안내한다. 저장 실패와 서버 지연은 재시도 상태를 제공한다.

## 8. 여행 플래너

### 여행 목록

- 제목, 시작·종료일, 계획 중·여행 중·완료 상태
- 새 여행 만들기, 수정, 삭제
- 상태별 목록과 빈 상태 안내

### 여행 상세

- 날짜별 장소: 활동·맛집·숙소·교통
- 장소명, 주소, 영업시간, URL, 방문 시각, 공유 메모, `통화 때 꼭 얘기`
- 방문 시각이 있는 장소는 시간순 자동 정렬
- 시각이 없는 장소는 위/아래 이동으로 수동 정렬
- 네이버지도 검색 링크 제공
- 체크리스트 추가·완료·삭제
- 여행 기간 기록을 `추억 보기`로 연결

### 지도 캡처 OCR

- 사용자가 올린 지도 캡처는 서버에 저장하지 않고 기기에서만 문자 인식
- 상호명·주소·영업시간 후보로 입력란을 채움
- 인식 결과는 사실로 확정하지 않고 사용자가 확인·수정한 뒤 저장
- 지도 API가 없어도 직접 입력과 링크로 전체 흐름이 동작

## 9. 우리와 복무

### 우리

- 두 사람의 프로필과 함께한 기간
- 기념일이 표시된 월 달력
- 다가오는 여행과 일정/여행 바로가기

### 복무 현황

- 군화 이름, 군종, 복무 상태, 입대일·전역일
- 오늘 기준 복무 진행률과 전역 D-Day
- 가장 가까운 휴가·면회 일정
- 권한 있는 사용자의 복무 정보 수정

## 10. 마이와 설정

- 테마 전환, 프로필 닉네임 수정
- 커플 공간 생성, 초대 코드 복사·재발급, 코드로 참가
- 일정·여행·복무 바로가기
- 내 기록 데이터 내보내기
- 커플 연결 해제
- 내가 작성한 기록 전체 삭제
- 계정 삭제 요청, 대기 중 복구, 최종 삭제 안내
- 이용약관·개인정보 처리방침

파괴적 행동은 설명→재확인→처리 결과 순서로 진행하고 일반 저장 버튼과 시각적으로 분리한다.

## 11. 공통 상태와 품질 규칙

| 상태 | 사용자에게 보여줄 것 |
| --- | --- |
| 로딩 | 무엇을 불러오는지 구체적인 문구와 스켈레톤 |
| 비어 있음 | 실패처럼 보이지 않는 설명과 다음 행동 1개 |
| 오프라인 | 마지막 동기화 데이터임을 알리고 가능한 행동 구분 |
| 저장 중 | 중복 입력을 막고 진행 상태 표시 |
| 저장 실패 | 입력을 보존하고 이유·재시도 제공 |
| 권한 없음 | 데이터 존재 여부를 노출하지 않고 안전한 이전 경로 제공 |
| 연결 해제 | 상대 데이터 즉시 제거, 개인 데이터 유지 범위 안내 |
| 동기화 지연 | 빈 상태로 단정하지 않고 확인 중임을 표시 |

- 모바일 320px 이상, 주요 터치 영역 최소 44px
- 접근성은 시각적 크기와 터치 영역을 분리해 해결한다. 작은 아이콘·칩은 투명 패딩이나 행 전체 클릭으로 44px 터치 영역을 확보한다.
- 화면 제목 20~22px, 섹션 제목 16~18px, 핵심 본문 15~16px, 일반 본문 14~15px, 메타 12~13px을 기본 범위로 삼고 사용자 글자 확대를 견딘다.
- 한 화면의 큰 카드 최대 3개, 카드 중첩 금지, 주요 CTA 최대 1개를 기본 수용 기준으로 삼는다.
- 거의 흰색인 따뜻한 배경과 딥 네이비 본문을 기본으로 하고 코랄=관계·주요 행동, 블루=계획, 민트=완료, 옐로=확인 필요, 빨강=오류·삭제의 의미를 유지한다.
- 파스텔은 작은 상태 배경과 선택 표시에만 쓰며, 큰 그라데이션 카드·의미 없는 장식·과도한 하트와 이모지를 사용하지 않는다.
- 키보드 조작, 포커스 표시, 라우트 이동 알림, 의미 있는 접근성 이름
- 밝은/어두운 테마와 텍스트 대비
- Supabase Auth·DB·Storage·RLS·Realtime 사용
- 외부 분석 이벤트에 기록 본문·감정·주소·첨부 파일을 보내지 않음

## 12. 검증 대기와 후보 기능

### 실제 환경 검증 대기

- 두 계정 초대·연결·권한·실시간 동기화
- 통화 확인점의 기기 간 기대 차이
- 모바일 브라우저 카메라·녹음·대용량 업로드 복구
- OCR 정확도와 사용자가 잘못 저장하지 않게 하는 확인 경험

### 후보 — 구현 전 사용자 검증 필요
