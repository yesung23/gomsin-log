# 다른 AI에게 붙여넣는 프롬프트

> 아래 `---` 사이를 **그대로 복사해서** 새 AI 세션의 첫 메시지로 붙여넣는다.
> 저장소 접근 권한이 있는 도구(Claude Code · Codex · Cursor · Kiro)를 전제한다.
>
> 이 파일 자체는 프롬프트가 아니라 **프롬프트를 담는 자리**다. 긴 판을 고칠 때는
> 첫 번째 `---` 사이를 고치고, 아래 짧은 판도 같은 규칙으로 맞춘다.

---

너는 지금부터 **곰신로그**라는 제품의 저장소에서 일한다. 시작하기 전에 아래를
그대로 따른다.

## 1. 먼저 읽어라 (순서대로)

0. 저장소 루트에서 `bash scripts/agent/session-start.sh` — live 브랜치·HEAD·PR·점유·최근
   작업을 먼저 읽는다. 문서에 적힌 휘발성 상태로 대신하지 않는다.
1. `CLAUDE.md` — 작업 규칙과 세션 절차.
2. `AGENTS.md` — engineering contract. 보안·데이터·범위·검증·종료 규칙은 여기에 있다.
3. `docs/WHAT_IS_GOMSINLOG.md` — 이 제품이 무엇이고 왜 이렇게 생겼는지.
4. `docs/V4_AS_BUILT.md` — 지금 화면이 실제로 어떻게 생겼는지.
5. `docs/V4_BACKLOG.md` — 남은 일과 무엇에 막혀 있는지.

`docs/PRODUCT_V3.md`는 제품 의도의 유일한 주인이지만 길고 규칙으로 쓰여 있다.
**처음부터 끝까지 읽지 말고** 지금 하려는 일과 관련된 절만 찾아 읽어라.
구현 순서·gate는 `docs/ENGINEERING_ROADMAP.md`, 현재 결함·미구현은
`docs/CURRENT_STATE.md`, 최근 관련 이력은 `docs/WORK_LOG.md`에서 확인한다. 사업·고객·
수익화·기억상품에 영향을 주는 일이라면 `docs/BUSINESS_MEMORY_ROADMAP_V1.md`도 읽는다.
세션 점유·보고가 필요하면 `docs/AI_SESSION_PROTOCOL.md`와 해당 `docs/skills/` 원본을 따른다.

## 2. 상태는 문서가 아니라 기계에서 읽어라

```bash
bash scripts/agent/session-start.sh
```

이 명령은 §1의 첫 단계로 저장소 루트에서 실행한다. 다시 실행해도 된다.
문서에 적힌 PR 번호·SHA·배포 상태·CI 결과는 **그때의 기록일 뿐이다.** 작업 시점에
다시 확인한다. 현재 구현 사실은 코드와 live 상태가 이긴다. 제품 의도·engineering
contract·보안 프로토콜은 각 canonical 문서가 소유한다. 서로 어긋나면 조용히 덮지 말고
충돌을 보고한다.

## 3. 이 저장소가 이미 다친 자리 — 같은 데를 다시 밟지 마라

아래는 이 저장소의 과거 감사에서 실제로 발견한 실패 패턴이다. 현재 테스트가 초록이어도
다시 동작과 실제 마운트를 확인한다. 상세 원장은 `docs/WORK_LOG.md`에 있다.

- **목(mock)이 결함이 사는 곳을 통째로 들어낸다.** 어떤 화면의 단위 테스트가 셸과
  자식 컴포넌트를 전부 목으로 갈아끼우고 있었고, 그 화면은 실제로는 크래시해서 **빈
  화면**이었다. 배치만 보는 테스트와 **실제로 마운트되는지** 보는 테스트를 같이 둬라.
- **소스 문자열을 뒤지는 테스트는 버그가 있는 내내 초록이다가 고치는 순간 깨진다.**
  규칙은 인라인 계산이 아니라 **이름 있는 순수 함수**로 꺼내서 실행해 확인해라.
- **TypeScript는 JSX의 하이픈 붙은 속성(`data-*`)을 검사하지 않는다.** 컴포넌트가
  통과시키지 않으면 타입 검사를 통과하고 화면에는 아무것도 안 붙는다.
- **기본 macOS 디스크는 대소문자를 구분하지 않을 수 있다.** `Foo.tsx`와 `foo.ts`가
  충돌하고, 그때 나오는 오류는 "쓰지 않는 변수"처럼 보여 아무도 경로 충돌을 안 볼 수 있다.
- **마이그레이션은 해당 harness 체인에 추가해야 검증된다.** 파일을 쓰고
  `npm run test:phase0`가 초록이어도, 체인 목록과 `supabase/migrations/README.md`에
  반영하지 않았으면 **실제 체인에 적용·검증된 것이 아니다**.
- **거절을 확인하는 테스트는 서로 다른 열쇠를 써라.** 같은 키를 쓰면 하나가 통과했을 때
  나머지가 규칙이 아니라 UNIQUE 제약 때문에 거절되어, 규칙을 빼도 초록으로 남는다.
- **기본 인자가 "값이 없음"을 삼킨다.** 테스트 헬퍼에 기본값을 주면 그 경우를 아무도
  검사하지 않게 된다.

## 4. 이 제품이 절대 하지 않는 것

어길 것 같으면 **짓기 전에 멈추고 물어라.**

- **부재를 알리지 않는다.** 상대가 아무것도 보내지 않은 날에 "오늘은 신호가 없어요"
  라고 쓰지 않는다 — 그것 자체가 상대가 말하지 않았다는 사실을 알리는 일이다.
- **관계나 상대의 반응을 점수·활동량으로 수치화하지 않는다.** 좋아요 수·조회 수·연속
  기록·본 사람 목록·열람 시각을 두지 않는다.
- **기계가 추론한 감정은 작성자가 결정한다.** 기본적으로 작성자에게만 보이며, 작성자가
  선택·확인했거나 저장될 감정이 화면에 보이고 끌 수 있었던 상태에서 저장한 경우에만
  공유될 수 있다. 세부 규칙은 `PRODUCT_V3` §13·§13.1이 소유한다.
- **없는 것은 없다고 말한다.** 기념일이 없으면 지어내 세지 않는다.
- **자리를 바꾸면 인스타 문법을 빌려온 이유가 사라진다.** 탭을 옮기려면
  `docs/PRODUCT_V3.md` §5와 `docs/V4_AS_BUILT.md` §6.1을 모두 읽고 방향 충돌을 먼저
  확인하라 — 이미 세 번 갈아엎고 되돌렸다.

## 5. 하지 말 것

- **운영(Production) Supabase를 바꾸지 마라.** 마이그레이션 **작성·로컬 검증**은 되고
  **적용**은 이 프롬프트를 따르는 AI의 작업 범위가 아니다. 저장소·로컬·테스트·원격
  Supabase·Production·실기기 증거를 분리하고, 보고할 때 `적용됨`과 `커밋됨`을 섞지 마라.
- **`master`에 직접 push 하지 마라.** 브랜치와 PR로 간다.
- 041/042는 frozen이다. 재사용하지 마라.
- 별도 디자인 작업이 아니면 시각 아이덴티티·색·타이포·간격·레이아웃·탭 모양을
  재설계하지 마라. 기능 작업에서 UI를 임의로 갈아엎지 마라.
- 인증·E2EE·RLS·건강 데이터·계정 lifecycle·migration 작업은 관련 specialist 문서와
  gate를 먼저 읽어라. 평문 fallback·secret 노출·보안 약화는 허용하지 않는다.
- 검증하지 않은 것을 검증했다고 쓰지 마라. **실행한 것과 실행하지 않은 것을 구분해서**
  적어라.

## 6. 끝낼 때

변경 범위에 맞는 검증을 실행한다. 코드 변경이면 `npm run verify`, 문서만 바꿨으면
`scripts/agent/validate.sh docs`를 실행한다. 실행할 수 없으면 PASS라고 쓰지 말고
`UNVERIFIED`와 이유를 적는다.

`docs/WORK_LOG.md`에 표준 항목 하나를 남긴다. 현재 구현·결함·gate·blocker가 바뀌었으면
`docs/CURRENT_STATE.md`도 갱신하고, 단계·진입 조건이 바뀌었으면
`docs/ENGINEERING_ROADMAP.md`, migration 원장이 바뀌었으면
`supabase/migrations/README.md`를 갱신한다. 무엇을 실제로 실행했고 무엇을 실행하지
않았는지 반드시 구분해서 적는다. 문서 작업은 `scripts/agent/validate.sh docs`와 함께
변경 문서의 내부 링크·인용 경로도 직접 확인한다.

비사소한 작업은 시작 전에 `bash scripts/agent/claim.sh <agent> "<scope>"`로 점유하고,
끝나면 `bash scripts/agent/claim.sh --release <agent>`로 놓는다. 종료 시
`docs/AI_SESSION_PROTOCOL.md` §8의 전용 Control Tower memory worktree에
`control-tower/reports/<agent>/` 표준 리포트를 직접 남기고
`bash scripts/agent/ct-sync.sh push "ct: <agent> <요약>"`로 공유한다. 공유 worktree가
막히면 현재 작업 worktree에 복사하지 말고 작업을 실패로 처리하지도 말며,
`READY-TO-COPY` 리포트를 출력한다.
