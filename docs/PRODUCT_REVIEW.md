# 곰신로그 제품 검토 — 무엇을 더 만들고 무엇을 멈출 것인가

## 결론

현재 서비스의 기록·감정·원문 연결은 핵심 가치에 맞는 좋은 기반이다. 하지만 일정·여행·위젯이 같은 중요도로 늘어나면 “무엇이든 있는 커플 앱”이 되고, 군화의 제한된 시간을 아껴준다는 차별점이 약해진다.

따라서 최선의 방향은 **기능 추가 경쟁이 아니라 통화 맥락 루프의 완성도와 실제 기록 중심의 시각 경험**에 집중하는 것이다. 시각 기준은 `docs/design-references/clean-couple-ui-reference.jpg`의 정보 밀도와 타임라인 문법을 참고한다.

## 1. 현재 잘된 점

- 글·사진·영상·음성으로 비동기 기록 가능
- 군화가 실제 원문과 미디어를 확인 가능
- 감정은 작성자가 확인한 것만 공유
- 비공개 기록의 서버·클라이언트 이중 격리
- 요약에서 근거 원문으로 이동
- 일정·여행을 둘만의 공간에서 관리
- 생성형 AI 없이 규칙 기반으로 무료 운영 가능

## 2. 기존 구조의 문제

### 오늘만 보는 브리핑

군화가 매일 앱을 볼 수 있다는 가정은 맞지 않는다. 오늘 기록만 요약하면 며칠간 놓친 맥락을 복구하지 못한다.

조치: 최근 7일과 마지막 통화 체크포인트 이후의 기록을 기준으로 변경했다.

### 중복 위젯

상대의 오늘, 감정 흐름, 오늘의 요약, 다정한 첫마디가 각각 같은 맥락을 반복한다. 군화가 모든 카드를 읽으면 시간을 아끼지 못한다.

조치: `통화 전 60초`에 마음·핵심 맥락·첫마디를 통합하고 홈 상단에 고정했다. 기존 위젯은 상세 탐색용으로 유지했다.

### 중요도를 앱이 추측

반응값과 질문표로 우선순위를 정할 수 있지만 곰신이 정말 통화에서 다루고 싶은지 완전히 알 수는 없다.

조치: 기록·일정·여행 장소에 `통화 때 꼭 얘기`를 구현했다. 사용자의 명시 표시가 자동 우선순위보다 앞선다.

권고: 다음 파일럿에서 이 표시의 실제 사용률을 먼저 보고, `그냥 들어줘 / 같이 생각해줘 / 답이 궁금해` 같은 대화 의도는 별도 검증 뒤 결정한다.

### 체크포인트가 기기별

현재는 비용과 마이그레이션 없이 검증하기 위해 기기에만 저장한다. 다른 기기 또는 앱 재설치에는 이어지지 않는다.

권고: 체크포인트 사용률이 높을 때만 Supabase 동기화 테이블을 추가한다.

### 과대 UI와 AI 템플릿처럼 보이는 기록

접근성을 해결한다는 이유로 제목·버튼·카드 높이를 일괄 확대하면 한 화면에 보이는 정보가 줄어들고, 젊은 커플 앱보다 시니어 모드나 업무 대시보드처럼 느껴진다. 또 모든 기록을 같은 둥근 카드, 파스텔 배지, 앱이 만든 제목으로 감싸면 사용자가 남긴 사진과 문장이 제품의 주인공이 되지 못한다.

조치:

- 가독성은 본문 14~16px과 충분한 대비로 확보하되, 터치 영역 44px은 투명 패딩과 행 전체 클릭으로 분리한다.
- 기록은 `시간 → 미디어 → 작성자·원문·상태` 타임라인을 기본으로 하고 개별 기록마다 큰 카드를 만들지 않는다.
- 앱의 요약·질문·감정 파생값은 사용자 원문보다 작고 보조적인 위치에 둔다.
- 큰 카드 최대 3개, 주요 CTA 최대 1개, 강조색 최대 2개를 대표 화면 수용 기준으로 삼는다.
- 의미 없는 그라데이션, 반복 하트·이모지, 과도한 파스텔 카드와 넓은 빈 공간을 제거한다.

## 3. 경쟁 서비스와의 차이

- Between: 비공개 채팅·사진·기념일·공유 일정이 중심이다.
- Paired 계열: 매일 질문·퀴즈·게임으로 대화 소재를 제공한다.
- 곰신로그: **실제 상대의 하루를 짧게 따라잡고 현실 통화의 질을 높이는 것**이 중심이다.

따라서 질문 콘텐츠 수, 채팅, 테마 경쟁을 따라가면 안 된다. 실제 기록에 근거한 `놓친 맥락 압축`이 제품의 방어력이다.

## 4. 개발 우선순위 제안

### 지금 구현한 것

1. 군화 홈 고정 `통화 전 60초`
2. 최근 7일·체크포인트 이후 새 소식
3. 중요 맥락 최대 3개
4. 원문 이동
5. 근거 기반 첫마디
6. 통화 완료 체크포인트
7. 곰신 작성 가이드
8. 320px·라이트/다크·시맨틱 색상과 타입 스케일 자동 검증

### 다음으로 검증할 것

1. `통화 때 꼭 얘기` 표시를 곰신이 실제로 사용하는가?
2. `그냥 들어줘 / 같이 생각해줘 / 답이 궁금해`가 통화 오해를 줄이는가?
3. 체크포인트가 통화 직후 자연스럽게 눌리는가?
4. 3개 맥락이 충분한가, 2개가 더 나은가?
5. 일정 또는 여행의 `결정 필요` 한 줄이 브리핑에 유용한가?
6. 사용자가 기록 화면에서 앱의 설명보다 사진·음성·상대 원문을 먼저 발견하는가?
7. 새 화면 밀도가 “너무 크고 둔하다”거나 “AI 템플릿 같다”는 인상을 줄이는가?

### 당분간 만들지 않을 것

- 앱 내 채팅·통화: 카카오톡과 전화의 열등한 복제품이 될 가능성이 큼
- AI 장문 요약: 비용·개인정보·환각 위험 대비 현재 가치가 불명확
- 공개 장소 추천 피드: 핵심 통화 가치와 무관하고 운영비가 큼
- 감정 점수: 근거 없는 정량화로 관계 오해를 만들 수 있음
- 연속 접속 보상: 기록 의무감과 죄책감을 만들 수 있음

## 5. 2주 검증 계획

대상: 실제 군화·곰신 3~5쌍

### 기준선 3일

- 기존 방식으로 통화
- 설명에 든 체감 시간, 놓친 맥락, 통화 만족을 각각 1~5로 기록

### 기능 사용 10일

- 곰신은 평소처럼 순간 기록
- 군화는 통화 전 60초 브리핑 확인
- 통화 후 체크포인트

### 판단 기준

- 80% 이상의 브리핑이 60초 안에 완료
- 곰신의 `처음부터 설명했다` 점수가 기준선보다 감소
- 군화의 `무엇을 물을지 알았다` 점수가 증가
- 기록 횟수를 강제로 늘리지 않아도 효과가 유지
- 비공개 또는 잘못된 감정 해석 사고 0건
- 390×844 첫 화면에서 군화가 브리핑 완료 행동과 실제 기록 일부를 함께 발견
- 대표 사용자 다수가 새 UI를 “정돈됐다·젊다·한눈에 보인다”고 평가하고 “시니어 모드 같다·업무 앱 같다·AI스럽다”는 반복 의견이 없음

성공하면 대화 의도 표시와 서버 체크포인트를 검토한다. 실패하면 AI를 붙이지 말고 항목 수, 선택 규칙, 작성 안내부터 수정한다.

## 6. 무료 운영 판단

- 현재 통화 브리핑은 클라이언트 규칙 계산이므로 API 비용이 없다.
- 체크포인트는 확인한 기록 ID와 시각을 담은 작은 로컬 JSON이라 서버 비용이 없다.
- 기존 Supabase 데이터만 사용한다.
- OCR도 기기 안에서 처리한다.
- 외부 분석을 도입해도 본문 없이 성공 여부와 시간만 집계해야 한다.

이 구조는 초기 사용자 검증을 무료에 가깝게 진행하기에 적합하다.

## 7. 참고한 현재 시장 자료

- Paired는 매일 질문·퀴즈·게임을 통해 대화 주제를 만드는 방향이다: https://www.paired.com/
- Between은 둘만의 채팅·사진·기념일·공유 일정을 한 공간에 모으는 방향이다: https://between.us/?lang=en
- Paired 무료 버전은 제한된 일일 대화를 제공하고 더 많은 콘텐츠를 구독으로 확장한다: https://support.paired.com/en/articles/164633-what-s-paired-premium

곰신로그는 이 두 방향을 그대로 복제하지 않고, 군 복무로 생기는 비대칭적인 시간 조건과 `통화 전 놓친 맥락 복구`에 집중한다.
