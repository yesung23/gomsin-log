## 1. Product Core

### 1.1 곰신로그의 진짜 가치

> **함께하지 못한 하루를, 상대가 폰을 잡는 첫 1분 안에 이해할 수 있는 브리핑으로
> 바꾸고, 그 이해가 다음 실제 통화로 이어지게 하며, 그렇게 이어진 하루들이
> "함께 기다린 시간의 증거"로 눈에 보이게 쌓이는 것.**

세 개의 가치가 하나의 사슬이다: **복구(브리핑) → 연결(통화) → 축적(우리)**.
어느 하나만 있으면 기존 제품과 다르지 않다. 셋이 이어져 있는 것이 곰신로그다.
그리고 이 사슬 전체가 **감시 없이** 동작한다는 것 — 읽음 표시 없음, 접속 추적 없음,
관계 판정 없음, E2EE 방향 — 이 지속 가능한 신뢰 우위다.

### 1.2 기존 앱보다 잘 푸는 문제

| 대안 | 왜 이 문제를 못 푸는가 |
|---|---|
| 카카오톡 / Instagram DM | 대화의 저장소이지 하루의 저장소가 아니다. 밀린 스크롤백을 다시 읽는 것 자체가 "재설명 부담"이다. 따라잡기 화면이 없다 |
| Between류 커플앱 | 채팅+앨범 중심. 비동기 브리핑·정확한 원본 이동·대화 예고 개념이 없고, 광고 기반이며 E2EE가 아니다 |
| SumOne류 질문앱 | 매일 질문을 **제조**한다. 실제 하루가 아니라 콘텐츠 트레드밀이고, 연속 기록 압박이 정체성이다 |
| 군 D-Day/정보 앱 | 행정·달력 유틸리티. 관계의 실체(기록·사진·대화)가 없다 |
| 사진 클라우드 | 저장은 하지만 관계의 의미 단위(하루·달·마일스톤)가 없다 |

곰신로그만 하는 것: **놓친 구간 기준의 결정적 요약 → 정확한 원본 → 이따 이야기하기 →
통화**라는 목적 있는 경로. 그리고 그것을 감시·점수·광고 없이 하는 것.

### 1.3 곰신로그가 절대 되지 말아야 하는 것 (정체성 울타리)

`PRODUCT_V3` §16을 비준하고, 여섯 문장으로 고정한다.

1. **메신저가 아니다.** 출구는 항상 앱 밖의 통화·만남이다.
2. **피드가 아니다.** 무한 스크롤·알고리즘 정렬·좋아요 경제를 만들지 않는다.
3. **감시탑이 아니다.** 읽음·접속·부재를 상대에게 알리는 순간 제품이 죽는다.
   곰신은 "닿았다"까지만 알 수 있고, "읽었다"는 영원히 알 수 없다.
4. **판정자가 아니다.** 기계는 사실을 정리할 뿐, 마음과 관계를 단정하지 않는다.
5. **저장 장사꾼이 아니다.** 바이트·보안·데이터 권리를 인질로 잡지 않는다.
6. **군 포털이 아니다.** 군 복무는 초기 사용 사례이지 정체성이 아니다.

## 5. 프라이버시·데이터 아키텍처

### 5.1 지금의 정직한 현실 (코드 감사 결과)

신뢰 포지셔닝의 전제는 **주장과 현실의 일치**다. `d45c760` 기준 현실:

| 층 | 현실 |
|---|---|
| daily_records E2EE | **구현됨, 그러나 feature flag 기본 OFF** (`VITE_E2EE_DEVICE_PROTECTION_ENABLED` 미설정) + native 전용 ceremony |
| 커플 키 페어링 · 2기기 등록 · 파트너 보조 복구 · 기기 폐기 | **도메인 계층 완성 + 테스트 완비, UI 호출자 0** (`useCases.ts` 2,844줄이 제품에서 도달 불가) |
| 사진·미디어 | 평문 저장 (private bucket + RLS + EXIF/GPS 제거) — P6 미착수 |
| 주기·건강 | 평문 저장 (RLS + 동의 게이트 + 타입 수준 projection 최소화) — HRK 키는 존재하나 제품 데이터가 안 씀 (P8) |
| 운영 DB | 마지막 확인(2026-08-11) 기준 migration ~027. 028–047 미적용. Storage SELECT 정책 부재 기록 |
| push | 의존성·코드 전무 (Gate 3 신규) |

따라서 **"E2EE 앱"이라는 문장은 아직 어떤 사용자에게도 사실이 아니다.** 이것은
실패가 아니라 순서의 문제지만, 밖에 말할 때의 문장은 단계별로 정확해야 한다 (§5.4).

### 5.2 구조 결정 — 공유와 보존의 분리 (ARCH-P6 개정 채택)

`PERSONAL_CLOUD_EVALUATION`의 발견을 **정식 채택**한다. `CKShare`는 Apple 계정 간에만
동작하므로 ARCH-P6의 "CKShare read-only partner"는 iPhone+Galaxy 커플 가입 첫날부터
동작하지 않는다. 결정:

```text
공유 경로 (필수 · 플랫폼 중립 · 유일)
  기기 → EXIF 제거·정규화 → E2EE(GME1) → 중립 암호문 blob 저장(Supabase Storage 등)
  → Supabase 조율 메타데이터 → 파트너 복호
보존 경로 (선택 · 플랫폼별 · 없어도 제품 완결)
  iOS: iCloud(자기 암호문 백업) / Android: Drive appDataFolder 후보 — M5 PoC가 결정
```

- 키 계층(PMK/CSK/HRK)·envelope·device bootstrap·RLS는 이미 플랫폼 중립이다. 불변.
- 보존 경로는 **키를 절대 싣지 않는다.** 복구 권한은 recovery kit가 유일하다.
- iPhone+iPhone / Galaxy+Galaxy / 혼합 — 세 조합이 같은 공유 경로를 쓴다.
- `ENGINEERING_ROADMAP` ARCH-P6 절의 개정이 선행되어야 한다 (§11).

### 5.3 push 프라이버시 (PHASE_NEXT §1 비준)

행위만 알린다 · 관찰(읽음·접속·부재)은 영구 금지 · 이벤트 큐가 아니라 `has_unseen`
플래그 하나 · 하루 1회 상한 · **모든 이벤트가 동일한 단일 문구** (잠금화면 관찰자에게
이벤트 종류가 구분되면 안 된다 — 생활관 조건) · 배려 신호도 같은 문구 · 발신 Edge
Function은 콘텐츠 접근 권한 자체가 없다 · 연결 해제·로그아웃·계정 삭제·계정 전환 시
토큰 즉시 무효화 + negative test. 수신 시간은 학습이 아니라 `ContactPreferences`
(사용자가 직접 준 시간)만 쓴다.

### 5.4 단계별로 밖에 말할 수 있는 문장 (정직성 계약)

| 단계 | 말할 수 있는 것 | 말하면 안 되는 것 |
|---|---|---|
| LV | "글·사진은 서버 접근통제(RLS)로 보호되고, 사진의 위치정보(EXIF/GPS)는 업로드 전에 제거됩니다. 종단간 암호화는 정식 출시 전 단계적으로 적용되며, 검증 데이터는 종료 시 삭제/이관됩니다" | "E2EE로 보호됩니다" |
| Beta (기록 E2EE ON) | "글 기록은 종단간 암호화됩니다. 사진·건강 기록은 접근통제로 보호되며 암호화를 확대 중입니다" | "모든 데이터가 E2EE" |
| P6·P8 이후 + R5 감사 | "Full User-Content E2EE" | — (그때는 사실이다) |

계정 삭제·연결 해제 계약은 §14.4를 그대로 쓴다: **연결 해제는 삭제가 아니고, 이미
전달된 것은 회수할 수 없으며, 모든 기기와 kit를 잃으면 복구 불가가 정답이다.**

### 5.5 LV의 E2EE 결정 (이 문서의 가장 논쟁적인 결정)

> **LV 코호트는 device-protection flag OFF로 달린다.** 개발자 커플(dogfood)만 native에서
> ON으로 실사용해 ceremony를 검증한다. Beta부터 ON이 기본이 된다.

이유: (1) 커플 키 페어링·복구의 **UI가 아직 없다** — 지금 ON은 물리적으로 커플에게
배포 불가능하다. (2) LV의 목적은 루프 가치 검증이지 암호 프로토콜 검증이 아니다.
(3) recovery kit 분실 = 데이터 소실을 검증 참가자에게 지우는 것은 LV 단계의 지원
부담·신뢰 리스크로 부적절하다. (4) §5.4의 문장으로 정직성은 유지된다.
대가: M1(개인정보 보호 먼저)의 서사가 "개발 완료·적용은 Beta"로 조정된다. 수용한다.
페어링·복구 UI 완성은 Beta 진입 조건으로 이동한다 (Phase 3).

## 6. 리텐션 루프 — 닫히지 않은 화살표의 전수 목록

```text
[하루]  기록 → ①push → 브리핑 → 원본 → 이따 이야기하기 → ②통화 모드 → 이야기했어요
[한 달] 달이 끝남 → 우리 달 블록 → ③이 달 다시 보기 → (M7) 기억상품
[관계]  100일·휴가·1주년 → ④전역 recap → ⑤조용한 전환
        그리고 이 전부를 관통하는 ⑥측정
```

| # | 빠진 링크 | 상태 | 소유 Phase |
|---|---|---|---|
| ① | Push — 루프의 첫 이벤트. 앱이 닫혀 있으면 아무것도 전달되지 않는다 | 미구현 (의존성조차 없음) | **Phase 1 (Gate 3)** |
| ② | 통화 모드 — 마지막 화살표. 완료 처리 마찰로 보관함이 쌓이기만 한다 | 미구현 | **Phase 1 (Gate 4)** |
| ③ | 이 달 다시 보기 — 축적을 회고로, 회고를 (나중에) 상품으로 | 미구현 | Phase 3 |
| ④ | 전역 recap — 이탈일을 정점으로 | 미구현 | Phase 3–4 |
| ⑤ | 전역 후 조용한 전환 — 억지 리텐션 없는 잔존 | 미구현 [신규] | Phase 3–4 |
| ⑥ | **§19 허용 목록 안의 최소 계측 — 지금 0줄이다.** 계측 없는 LV는 연극이다 | 미구현 [신규 발견] | **Phase 1** |
| ⑦ | ⟨대기⟩ 구간 (S4) — 연결 완료율 직결 | 미구현 | Phase 1 |

**리텐션의 원칙은 유지한다: 알림 빈도가 아니라 쌓인 것의 가치가 리텐션이다.**
부재는 이벤트가 아니다 — 연속 기록·독촉·리인게이지먼트 알림은 구조적으로 불가능하게
남긴다 (`has_unseen` 모델이 이를 보장한다). 한쪽이 멈추면 루프가 죽는 것은 이 제품이
받아들인 대가다. LV가 그 자연 감쇠율을 **정직하게** 재야 한다.

집행 규칙 추가:

1. **감정적 순간에 압박 판매 금지.** 전역 D-7 카운트다운 할인 같은 것은 §16 위반으로
   본다. 제안은 IA §6의 "조용한 한 줄" 문법만 쓴다.
2. **전역 기억책이 실물 플래그십, 우리의 한 달이 반복 디지털 상품**이라는 가설 순서를
   유지하되, 검증은 디지털 먼저(§9.4 비준).
3. 인앱 디지털 상품의 스토어 수수료(~15–30%, 한국 대체결제 시에도 ~26%)가 저단가
   디지털 상품의 기여이익을 바꿀 수 있다 — P-MP 시작 시점에 웹 결제 허용 범위를
   포함해 **실측 항목**으로 확정한다(사업문서 §9.4의 검증 항목을 재확인). 실물 POD는
   IAP 의무 대상이 아니므로 외부 결제가 정상 경로다.
4. 내보내기는 영원히 무료다. 기억상품은 내보내기의 상위 호환이 아니라 별개의
   **제작 경험**이다.

## 9. 기술 아키텍처 리뷰

### 9.1 유지한다 (강점 — 되돌리지 말 것)

- **스택**: React 19 + Vite + Capacitor 7 + Supabase. 이 팀 규모·이 제품에 옳다.
- **커플 단위 데이터 분할**이라는 구조적 행운: 모든 제품 표면이 커플 하나의 데이터만
  본다. 요약 재계산·격자·브리핑이 사용자 수와 무관하게 O(커플)이다. 서버 확장
  리스크는 저장 egress와 push fan-out뿐이고 둘 다 선형·저가다.
- **결정적 클라이언트 계산** (요약 무캐시), **outbox의 기록 한정 + LCK 암호화**,
  **fail-closed write floor**, **crypto 계층 분리**(domains/GLE1/GLK2/cert),
  **module-per-domain 데이터 계층 + E2EE repository**.
- **테스트 문화**: 소스:테스트 ≈ 1:0.92, SQL 모델 기반 migration 계약 테스트 13종,
  디자인 토큰·접근성·CSP·타입 스케일의 실행 가능한 가드, mutation 검증 습관.
  canonical을 테스트로 강제하는 습관(`productValueAlignment.test.ts`)은 이 저장소의
  발명품이며 지켜야 한다.
- **외부 SDK 0** (분석·크래시·광고·AI). 계측은 §19 안에서 1st-party로만 (Phase 1).

## 10. 최종 결정

### 10.1 단 하나의 제품 방향

> **곰신로그는 "떨어져 있는 하루를 다음 통화로 잇는 브리핑"이고, 그 하루들이
> "함께 기다린 시간의 증거"로 쌓이는 둘만의 사적 공간이다. 성공의 단위는 체류 시간이
> 아니라 이어진 통화이고, 수익의 단위는 저장 바이트가 아니라 완성된 기억이다.**

### 10.2 다음에 만들 세 가지 (이 순서대로)

1. **Push + 통화 모드** — 루프의 첫 화살표와 마지막 화살표. 보안·migration gate 포함
   (Phase 1). 이것 없이는 지금까지 만든 모든 것이 "열어본 사람"에게만 존재한다.
2. **측정 가능한 LV** — 최소 계측 + LV 환경 + 실기기 빌드 + 실제 커플 5–15쌍
   (Phase 1→2). 다음 큰 투자(P6·BM)는 전부 이 증거 위에서만 정당화된다.
3. **사진 E2EE(개정 ARCH-P6) + 페어링 UI = Beta의 프라이버시 사실화** (Phase 3).
   "E2EE 앱"이라는 문장을 처음으로 사실로 만드는 작업이다.

### 10.3 중단·금지 목록

| 항목 | 상태 |
|---|---|
| 자체 채팅 | FROZEN 유지. LV 증거 전 재개 논의 금지 |

5. 그 외 2026-08-20 결정군은 **비준**이다. 재론하지 않는다.
