## 1. 한 문장

인스타그램의 **골격**을 그대로 쓰고, 그 골격이 **공책 위에 펜으로 그려져** 있다.

바뀌는 것은 그것이 무엇 위에 그려졌는가뿐이다. 헤더 56px, 스토리 레일 106px, 포스트의
세로 순서(작성자 54px → 사진/글 → 액션 44px → 캡션 → 시간) — 이 숫자들이 인스타를
인스타로 보이게 하고, 이 앱은 그것을 바꾸지 않는다.

**왜 빌리는가.** 인스타를 쓰는 사람은 왼쪽 끝이 홈이고 가운데가 만들기이며 오른쪽 끝이
자기 프로필이라는 것을 **손으로 안다.** 그 기억을 그대로 쓰는 것이 학습 비용을 0으로
만든다. 자리를 바꾸면 빌려온 이유 자체가 사라진다 — 실제로 한 번 바꿨다가 되돌렸다(§6).

**빌리지 않는 것.** 팔로워·좋아요 수·조회 수·본 사람 목록·자동 재생·친구 추천. 전부
`PRODUCT_V3` §16의 비목표다. **자리는 빌리되 개념은 빌리지 않았다.**

## 2. 탭바 — 다섯 자리

```
인스타      홈      검색      만들기(+)     릴스      프로필
곰신로그    홈      찾기      일기장        일정      우리
경로        /home   /search   /diary        /schedule /us
```

| 칸 | 무엇 | 인스타의 그 자리인 이유 |
|---|---|---|
| 1 홈 | 스토리 레일 + 게시물 지면 | 같음 |
| 2 찾기 | 날짜·글로 내 기록 찾기 | 검색 자리. 단 **남의 것이 없다**(§4) |
| 3 일기장 | 월별 모음 → 날짜별 다이어리 페이지 | 기록을 날짜별로 고르고 순서를 정해 종이·레이아웃으로 엮는 곳. 종이 보관함(`/shop`) 연결 |
| 4 일정 | 달력·다가오는 일 | 릴스 자리. 다른 넷은 과거·현재인데 일정만 미래다 |
| 5 우리 | 커플 프로필 | 프로필. **아이콘이 아니라 커플 아바타**다 |

마지막 칸이 아이콘이 아닌 이유: 아이콘 다섯을 나란히 두면 그 칸이 "설정"처럼 읽힌다.
프로필 탭은 설정이 아니라 **우리 자신**이다.

**섹션 유지.** `matchPrefixes`가 상세 화면에서도 탭을 켜 둔다. 꺼지면 앱이 "당신은 아무
데도 없다"고 말한다.

```
홈    /home · / · /call · /saved
찾기  /search · /record
일기장 /diary · /shop
일정  /schedule · /trips
우리  /us · /me · /service · /my · /settings
```

`/compose`만 어느 탭에도 걸리지 않는다 — 동작이지 장소가 아니기 때문이며, 그 예외는
`settingsRouteReachability.test.tsx`에 이유와 함께 적혀 있다.

## 3. 화면별 구조

### 3.1 홈 — `src/features/home/PaperHome.tsx`

```
헤더 56px       곰신로그(손글씨)              🔖 이야기할 것   📞 통화
스토리 레일 106px  ( + )내 스토리    ( )상대
─── 손으로 그은 선 ───
포스트          아바타 34 · 이름 ────────────── ⋯
                사진(전폭) 또는 글이 그 자리를 차지
                이름 없는 캡션
                오늘 HH:mm · 원본 44px · 책갈피 44px
```

- **내 스토리가 맨 왼쪽.** 인스타에서 왼쪽 끝은 언제나 자기 자신이고 `+` 배지가 거기
  붙는다. 한 번 상대를 왼쪽에 뒀다가 되돌렸다.
- **링은 정확히 둘.** 인스타라면 여기부터 팔로우한 사람들이 이어지지만 이 앱에는 두
  사람뿐이라 그 자리가 비고, **비는 것이 맞다**(§5.2).
- **링 상태는 내 쪽의 사실만 말한다** — 아직 안 본 것이 있는가. 열람 시각도 읽음 표시도
  아니다(§16). 상대는 내가 봤는지 알 수 없다.
- **사진이 없으면 글이 그 자리를 차지한다.** 빈 사진 틀은 로딩 실패처럼 보인다.
- **사진 포스트는 사진 → 글 → 동작 순서다.** 홈과 스토리 레일에 이미 보이는 작성자 이름을
  캡션에서 반복하지 않고, 시각은 상대 날짜 문맥을 유지하되 초를 버려 `HH:mm`까지만 표시한다.
- **액션 줄에 숫자가 없다.** 공감·토닥이기는 아직 데이터 모델에 없어서 **버튼을 두지
  않았다** — 눌러도 아무 일이 없는 하트는 보낸 줄 아는 사람에게 거짓말이다. 실제로
  동작하는 `이따 이야기하기`만 있다.
- **지면이 담는 구간은 최근 7일**, 그중 스토리가 가진 것(상대의 미확인 구간)은 뺀다.
  경계는 날짜가 아니라 **확인 여부**다(§6.1).

### 3.2 스토리 — `src/features/story/`

```
첫 장    하루 요약 (처음 5줄, 각 줄이 그 순간으로)
  ↓ 옆으로
순간들   시간순. 각 카드에서 `원본 열기`
닫는 카드
```

§6.1의 두 층 **(A) 요약**과 **(B) 원본**이 **둘 다 여기 있다.** 한때 (A)를 홈에 두려
했으나 그러면 스토리에 들어갈 이유가 없어진다 — 이미 다 본 것의 목차가 요약이 된다.

상대의 오늘이 한 날짜의 공개·복호 가능·서버에 저장된 기록 2개 이상일 때, iOS는 기존
규칙 요약 전체를 먼저 즉시 만들고 첫 5줄을 보여 준다. 나머지는 `N개 더 보기`로 펼친다.
온디바이스 기능은 `VITE_ON_DEVICE_DAILY_SUMMARY_ENABLED === 'true'`인 검증 빌드에서만
열리며 **스토리를 여는 것만으로 모델을 돌리지 않는다.** 표지의 `AI로 다듬기`를 누르는 순간
Foundation Models가 5개 고정 배치로 현재
규칙 문장의 표현만 다듬는다. 실행 중에도 규칙 요약은 그대로 보이고, 성공하면 같은 줄만
교체한다. 항목 수·순서·원본 ID 연결은 바꾸지 않는다.
네이티브 경계에는 배열 위치와 40자 이하 문장만 전달하며 record ID, 사용자 ID, 날짜, 시간,
첨부 URL, 비공개 기록, 건강·주기 원본은 전달하지 않는다. timeout·미지원·검증 실패 시 기존
규칙 문장을 그대로 유지한다. 값이 없거나 정확한 `true`가 아닌 빌드, 웹·Android에는 모델
경로와 AI 버튼이 없다. Xcode 26.6 Simulator compile은 PASS했지만 실제 지원 iPhone의 한국어
품질·지연·발열·배터리는 아직 검증되지 않았다.

순간 화면은 작성자 이름을 반복하지 않고 시각을 `HH:mm`까지만 표시한다. 사람의 기록 본문은
17px 본문 단계로 읽히며, 사진은 잘라 채우지 않고 전체가 보이도록 맞춘다. 책갈피·하이라이트·
원본 보기는 사진과 글 다음에 놓여 기록을 먼저 읽게 한다.

순간이 하나뿐이면 속표지를 붙이지 않는다. 목차가 목차 노릇을 못 한다.

### 3.3 남기기 — `src/features/compose/ComposePage.tsx`

전체화면 컴포저. 홈 레일 `+`, 우리 헤더 펜, 찾기 헤더 펜 및 기록 화면에서 상시 진입한다(§7.1).

```
✕        오늘 남기기                      [남기기]
[8월 23일] 오전 10:36
글 (손글씨, "오늘 어땠어?")
[ 사진 더하기 ]
─ ─ ─ ─ ─
오늘 마음 · 글에서 읽어봤어요
😊기뻤어  😮놀랐어  😰걱정됐어  😖별로였어  😠화났어  😢속상했어
─ ─ ─ ─ ─
[ ✓ 우리에게 공유 ]  [ 나만 보기 ]
```

- **순서가 인스타의 반대다.** 인스타는 사진이 필수라 갤러리가 먼저 오지만 여기서는
  **사진이 선택**이다. 사진 없는 날이 대부분이고 그런 날에도 남길 수 있어야 루프가 산다.
- **필수가 하나도 없다.** §7.1의 30초 계약. 마음도 사진도 손대지 않고 글만 쓰고 나갈 수
  있다.
- **감정 여섯이 늘 한 줄에 있고, 앱이 읽은 것만 미리 눌린다.** 글을 쓰고 필드를 떠나면
  분석이 돌고 해당하는 칸에 색이 들어온다. 틀리면 눌러서 끄고 다른 걸 누른다. 순서가
  흐름이다(§6.2) — `화났어 → 기뻤어`.
- **공개 범위는 접히지 않는다**(§7.2). 접어 두면 기본값으로 남기고, 기본값으로 남긴
  것이 상대에게 보인다는 사실을 나중에 알게 된다.
- **감정은 기록의 공개 범위를 그대로 따른다.** 별도 스위치를 뒀다가 없앴다 — 글은
  보여주면서 그 글에서 읽은 마음만 숨기는 상태는 뜻이 없다.
- 쓰던 글은 기기에 stash된다. 전체화면이라 뒤로 가기 한 번이면 사라지기 때문이다.

### 3.4 찾기 — `src/features/search/SearchPage.tsx`

검색 입력 한 줄과 결과. 입력하지 않았을 때는 역할에 맞는 정보를 먼저 보여주고, 입력하면
기존의 기록 검색으로 전환한다. **탐색 격자는 없다.**

**인스타에 검색 탭이 있는 이유는 거기에 남의 게시물이 있기 때문**이고 이 앱에는 남이
없다. 탐색 격자에 넣을 것이 우리 둘의 기록밖에 없어 `우리` 격자의 복제였다. 지웠다.

  - 군화는 입력 전 복무 현황·연락 가능 시간·다음 휴가/면회를 본다. 복무 카드는 입력한
    입대일·전역일과 화면이 공유하는 오늘 날짜를 기준으로 복무 상태, D-Day, 경과일·남은 일,
    입대일·전역일과 하나의 사실 기반 복무율 막대만 표시한다. 복무율은 최대 소수점 한 자리이며
    전역 상태는 정확히 100%다. EXP, Lv, 7단계 티어, 오늘 획득, 단계 전환 연출은 표시하지
    않는다. 정보가 없으면 날짜를 지어내지 않고 `/service` 입력 상태로 간다
  - 곰신은 입력 전 자신의 컨디션 신호·상대 배려 신호·주기 트래커를 본다. 상대 복무
    카드는 찾기 탭 주기 표면 앞에 위치하며, 로컬 작업 트리에 읽기 전용 UI(`SearchPage.tsx`),
    동기화(`sync.ts`), sanitized 허용목록 RPC(migration 063 `get_partner_service_info`)가
    구현되어 집중 로컬 테스트를 통과했다. 실제 입대일·전역일 기준 날짜 계산만 표시하고
    관계·애정도 점수는 없으며, 메모를 제외한 읽기 전용 복무 허용목록만 프로젝션한다.
    단, migration 063은 LOCAL FILE ONLY / NOT APPLIED(원격 프로덕션 Supabase 미적용) 상태이며,
    원격 Supabase 및 실기기(iPhone) 동작은 UNVERIFIED 상태다(미배포·미출시).
  - 곰신은 입력 전 '오늘 내 상태' 표면(내 컨디션 신호, 상대 배려 신호, 주기 트래커)을 본다.
    주기 원본과 본인 예상은 본인만 본다. 현재 생리 여부·예상 범위·가임 추정의 자동 파트너
    projection은 닫혀 있고, 상대에게 보낼 수 있는 것은 사용자가 그날 직접 고른 만료형
    배려 신호뿐이다
  - 입력하면 `8/14` 같은 날짜면 그날, 아니면 쓴 말에서 찾는다
- **기기 안에서만** 찾는다. 서버 전문 검색은 E2EE와 양립하지 않는다(§17)
- **최근 검색을 저장하지 않는다.** 자기 일기에서 무엇을 찾았는지는 그 자체로 사적이다
- 검색 결과를 보는 동안에는 역할별 기본 화면을 가리고 기존 검색 결과만 보여준다

### 3.5 일정 — `src/pages/SchedulePage.tsx`

```
[일정] [여행]        ← 인스타 프로필의 탭 줄 문법
2026년 8월        ‹  ›  +
일 월 화 수 목 금 토
… 오늘은 잉크로 채운 삐뚤한 사각형, 일정 있는 날엔 점
다가오는 일
복무율 (군 복무 커플만)
```

**빠른 할 일은 두 줄이다.** 제목이 한 줄을 다 쓰고, 시간과 버튼이 아래 줄을 나눠 갖는다.
한 줄에 나란히 두었더니 제목이 남는 폭을 전부 먹고 `<input type="time">` 이 80px 에 갇혀
`--:--` 가 잘렸다 -- 화면에서 **무시되는 컨트롤**이 됐다.

**`+`가 폼을 열지 않고 날짜 고르기를 켠다.** 끌면 범위가 잡히고 `다음`이 그 범위로 폼을
연다. 이벤트 모델이 이미 `startDate`+`endDate` 범위라 고른 것이 그대로 한 건이 된다.
휴가 3박 4일을 넣으려고 폼에서 종료일을 타이핑하던 순서가 없어졌다.

달력 문법은 이 앱에서 **여기만** 소유한다 — `우리`의 격자는 요일을 맞추지 않는다.

| 팔로워 | 만남까지 |
| 팔로잉 | 전역까지 |
| 프로필 편집 | 오늘 내 상태 |
| 프로필 공유 | 일기장 |
| 하이라이트 | 둘이 함께 고른 사진 묶음 (게시물 격자·스토리에서 가져오기) |
| 격자 | 작성자가 `+`에서 명시적으로 발행한 사진 게시물 |
| 격자/릴스/태그됨 탭 | `게시물 · 사진 · 여행` — 셋이 각각 다른 것을 그린다 |

- **인스타는 클수록 좋은 숫자만 있다.** 여기는 첫 칸이 쌓이고 나머지 둘은 줄어든다 —
  두 방향이 한 줄에 공존하는 것이 떨어져 있는 두 사람의 시간 감각이다. 셋 다 같은
  크기·같은 색이며 **줄어드는 숫자에 경고색을 쓰지 않는다.**
- **자물쇠는 자랑이 아니라 고지다** — 둘만 본다는 사실.
- **게시물 격자는 기록 전체를 반복하지 않는다.** 우리 화면의 `+`에서 사진을 고르고 글과
  공개 범위를 정해 **명시적으로 발행한 기록만** 인스타그램 게시물처럼 3열로 보인다.
  일반 스토리의 사진은 자동으로 들어오지 않고 `사진` 탭에는 그대로 남는다. 타일을 누르면
  `PhotoPostViewer`가 열리고, 기존
  `RecordMediaGallery`의 서명 URL·여러 장 넘기기·확대 동작을 재사용한다. 사진이 주
  내용이고 날짜·작성자·글은 보조 정보다.
- **하이라이트는 격자와 별개다.** 프로필에서 새 하이라이트를 만들거나 기존 하이라이트를
  편집할 때 게시물 격자의 사진을 고를 수 있고, 공유 사진 스토리를 보다가 `하이라이트에
  추가`를 눌러 같은 편집기로 가져올 수 있다. 비공개 기록은 클라이언트와 서버 양쪽에서
  선택하지 못한다. 현재 하이라이트 저장 단위는 `DailyRecord`이므로 한 기록에 여러 장이
  있으면 대표 커버는 그 기록의 첫 사진이다.
- **미래 하나는 언제나 남는다.** 기다림이 이 제품이고, 무엇을 기다리는지만 커플마다 다르다.
- **탭 줄의 셋은 전부 다른 것을 그린다.** `사진` 은 기존 기록을 최신순 목록으로 보여주고
  기록 상세·날짜별 타임라인으로 이어진다. `여행`은 현재·예정·지난 여행을 최대 세 개까지
  짧은 카드로 보여주며, 카드를 누르면 상세로 들어가고 `전체 보기`는 `/trips`로 간다.
  여행이 없으면 없다고 말하고 여행 플래너 진입만 남긴다. 사진 탭이 게시물 격자를 복제하지
  않도록 역할을 분리했다.
- **프로필 탭의 외곽은 변하지 않는다.** 선택 탭도 같은 테두리 공간을 차지하고 키보드
  포커스 링은 탭 안쪽에 그려져, 중간 탭을 눌렀을 때 탭 줄이 커져 보이지 않는다.

### 3.7 일기장 & 다꾸 상점 — `src/features/diary/` · `src/features/shop/`

하단 탭바 3번째 칸(`일기장`)은 쌓인 기록을 월별로 찾고, **날짜별 한 페이지**로 직접 엮는 곳이다.
원본 `daily_records`를 복제하지 않고 페이지 메타데이터만 계정별 기기 로컬에 둔다.

- **월별 카드 → 날짜별 페이지**: 기록이 있는 날짜를 골라 그날의 기록만 한 페이지로 읽는다.
- **페이지 편집**: 기록 포함/제외, 순서 변경, `기록 중심 · 사진 먼저 · 간결하게` 레이아웃을 고른다.
- **종이 5종과 무료 보관함**: 따뜻한 무지·줄 노트·모눈·도트·크림 편지지. 기본 무지/줄은 기존 사용자에게 계속 보유 상태이고, 나머지는 `/shop`에서 `무료로 받기`로 수집한다. 앱 전체 종이 선택의 직접 소유 화면은 `우리 → ⋯` 프로필 메뉴 하나이며 Settings에는 중복 선택기를 두지 않는다. 보유하지 않은 선택값이 남아 있으면 app/shop/profile 진입에서 보유 기본값으로 복구한다. `/shop`은 종이와 정원 장식을 모은 계정별 기기 로컬 무료 상점이고, 현재 모두 무료이며 결제 기능이 없다고 명시한다. 무료 starter 장식 5종은 미보유 항목만 남긴 회전판에서 하나씩 공개되며 중복·날짜 제한·마감·재화·결제는 없다. 결과 소유권을 먼저 기기에 저장하고 회전이 끝난 뒤 공개하며, 계정 전환과 저장 실패를 fail-closed 처리한다. 이전 버전 장식과 과거 `lastFreeDrawDate`는 보존하되 현재 수집을 제한하지 않는다.
- **기본 스티커 12종 무료 보존**: 기존 월 스티커 데이터는 지우지 않고 `기존 월 꾸미기` 모드에서 계속 쓴다. 날짜별 페이지 아래에 한 달 기록을 중복 렌더링하지 않는다.
- **로컬 프라이버시**: 페이지/종이/스티커 메타데이터는 로그아웃·계정 삭제 때 해당 계정 namespace를 함께 정리한다.
- **우리 정원**: `/diary/garden`은 현재 연결이 확인된 커플과 유효한 함께한 날이 있을 때만 열린다. 새 계정은 가운데 `나무 심기`를 한 번 실행하고, 저장에 성공하면 1·30·100·365일의 네 성장 그림과 단계 안의 일일 높이 변화로 중앙 나무가 자란다. 날짜 숫자·단계·설명 문구는 노출하지 않으며 364→365일에도 실제 표시 높이가 줄지 않는다. 하단 5탭을 숨긴 흰 전체 화면에는 뒤로가기와 놀기/꾸미기 아이콘, 나무, 두 캐릭터만 둔다. 두 친구는 별도 재그림이 아니라 보존 원본 `paper-pair-v1.webp`의 앞모습 두 영역을 정확히 크롭한 72×76px 시각물이고 조작 영역은 최소 44×44px다. `살구`와 `초록` 이름 및 가방 색으로 구분하며, 서로 겹치거나 경계를 벗어나지 않게 한 번에 한 친구만 이동한다. 걷기는 좌우 팔·다리를 반대 위상으로 교차하고, 직접 탭이나 가까운 만남은 부끄러워한 뒤 안전한 목적지로 뛰며, 잡힌 동안에는 몸 전체를 떨지 않고 네 팔다리가 독립적으로 버둥댄다. **500ms 연속 길게 누르기**는 pointer-captured drag를 시작하고 release/cancel/lost capture는 즉시 내려놓는다. 키보드·보조 기술 activation은 초점 복귀가 되는 sheet를 열며 `쓰다듬기 · 인사하기 · 같이 놀기`와 방향 이동을 제공하고 polite live region으로 결과를 알린다. `prefers-reduced-motion` 전환은 이미 예약된 shy/care timer까지 취소하고 자동·반복 모션을 끄되 정적 반응 표식과 직접 조작을 남긴다. 원본 시트의 `군화 · 운동화 · 편지 · 군번줄 · 비행기`와 기존 장식 중 이 계정이 실제 보유한 항목만 친구별 선택지에 노출된다. 심기와 장식은 version 2의 `gomsin.diary.garden.<userId>`에 저장되어 로그아웃·계정 삭제 purge 대상이며 version 1 장식 상태는 심어진 상태로 호환 로드한다. 나무 4종은 완성된 투명 WebP 각각 하나로 렌더하여 과거 crop-composite seam을 만들지 않는다. 배고픔·경험치·점수·스트릭·미션·실패·결제·AI·서버 정원 저장은 없다.
- **현재 숨김**: 유료 스티커 팩·다꾸 테마·기억책/기념앨범·결제 UI는 현재 V4 제품 표면에서 노출하지 않는다. V5에서 정원 상품과 Book Studio 진행은 승인됐지만 StoreKit·서버 entitlement·IP·앱 RC gate 전까지 활성화하지 않는다.

## 5. 시각 언어

주인은 [`DESIGN_V2.md`](DESIGN_V2.md)이고 여기서는 화면에서 보이는 것만 적는다.

**공책.** 괘선이 화면 전체에 깔리고 UI가 그 위에 그려진다. **카드가 배경을 채우지
않는다** — 채우는 순간 종이가 사라지고 다시 앱 화면이 된다.

설정의 `보기`에서 **무지 종이**를 고르면 따뜻한 종이색은 유지하고 괘선만 없앤다. 선택은
서버로 보내지 않는 계정별 기기 설정이고 즉시 적용되며 다시 실행해도 유지된다. 홈과 우리
화면의 상단 메뉴는 콘텐츠 스크롤 영역 안에서 고정된다.

같은 `보기`에서 게시물·Story 본문을 **작게 15px / 기본 17px / 크게 20px**로 고른다.
Home, Story, My 게시물 상세와 이전 feed의 사람이 쓴 본문에 함께 적용되며, 계정별 기기
로컬 값이라 서버·상대에게 전송되지 않는다. 시간·버튼·법적 문구는 기존 크기를 유지하고
긴 글은 잘리지 않고 다시 줄바꿈된다.

**여백선은 10px.** 진짜 공책은 27px 자리지만 인스타 레이아웃은 16px에서 시작해서 선이
글자를 가로질렀다. 내용을 밀어 피하면 인스타의 전폭이 사라지므로 **종이가 레이아웃을
피한다.**

**손으로 그린 선.** 네 모서리 반경이 서로 다르다. 반복되는 요소가 전부 똑같이 삐뚤면
그것은 다시 인쇄가 되므로 변형을 셋 두고 돌린다. SVG 필터가 아니라 CSS 반경만 쓴다 —
스크롤하는 목록에 필터를 걸면 기기에서 프레임이 떨어진다.

**손글씨는 사람이 쓴 글에만.** 시간·개수·버튼·법적 문구는 인쇄체다. 종이 일기장이 그렇듯
양식은 인쇄돼 있고 내용만 손으로 쓴다. 화이트리스트를 `handwritingScope.test.ts`가 지킨다.

**알림은 상태바 아래.** 앱 안 새 알림과 성공·오류 안내는 iPhone safe area와 56px 고정
헤더 아래에 8px 여백을 두고 표시한다. 다이내믹 아일랜드나 상단 메뉴 뒤에 숨지 않는다.

**밤에는 획이 굵어진다.** 밝은 획은 어두운 바탕에서 더 얇아 보인다(halation). 취향이
아니라 보정이다.

**잉크 대비는 계산이 정한다.** 눈으로 고른 값 셋이 WCAG 미달이었다(3.58 / 2.06 / 2.64).
`paperTokens.test.ts`가 CSS에서 값을 읽어 각 잉크의 **역할에 맞는** 최소 대비를 요구한다.

## 6. 계획에서 바뀐 것 — 그리고 왜

계획서(`EXPERIENCE_V4_MASTER_PLAN.md`)를 쓴 뒤 화면을 실제로 지으면서 세 번 바뀌었다.
**바뀐 이유가 다음 사람에게 중요하므로** 남긴다.

### 6.1 탭 세트를 세 번 갈아엎었다

```
계획      홈 · 찾기 · 남기기 · 일정 · 우리
2차       홈 · 나  · 일기장 · 일정 · 우리
최종      홈 · 찾기 · 남기기 · 일정 · 우리   ← 계획으로 복귀
```

2차로 간 이유는 타당했다 — 복무·주기·컨디션이 설정 안에 묻혀 있었고, 기억물이 §9.2의
1차 수익인데 자리가 없었다. 되돌린 이유는 **자리를 바꾼 대가가 더 컸기 때문**이다.
인스타를 쓰는 사람이 손으로 아는 다섯 자리를 흔들면 문법을 빌려온 이유가 사라진다.

내용은 사라지지 않았다. `나`와 `일기장`은 `우리` 안의 두 칩이 됐다 — 인스타의
`프로필 편집`·`프로필 공유` 자리다.

### 6.2 요약이 홈에서 스토리로 갔다

계획과 §6.1 개정은 "(A) 요약은 홈, (B) 원본은 스토리"였다. 화면에서 무너졌다 — 홈이
원본 타임라인을 통째로 그리고 있으면 **스토리에 들어갈 이유가 없다.** 이미 다 본 것의
목차가 요약이 되고, "같은 기록이 두 자리에 동시에 있지 않는다"는 §6.1 자신의 규칙도
어긴다. 두 층이 모두 스토리로 갔고 홈은 게시물을 갖는다.

### 6.3 감정 UI가 세 번 바뀌었다

```
1차   행복 · 놀람 · 공포 · 혐오 · 분노 · 슬픔   정서 연구의 분류명
2차   기뻤어 · 놀랐어 · … 를 카드로 확인          맞아요 / 다른 마음 / ✕
최종  여섯이 늘 한 줄, 읽은 것만 미리 눌림
```

1차: **`공포`나 `혐오`를 골라 자기 하루를 설명하는 사람은 없다.** 고를 수 없는 어휘는
고르지 않게 되고, 고르지 않으면 그 기능은 없는 것과 같다.

2차: 읽기 하나에 컨트롤이 셋이었다. 두 개가 읽히면 여섯 버튼을 지나야 저장에 닿는다 —
30초 계약에 그만한 자리가 없다.

최종: 토글 여섯뿐. "확인"이라는 별도 동작이 없어지는 대신 **여섯이 언제나 보이므로**
무엇이 저장될지 화면이 늘 말하고 있다.

`happiness`가 `좋았어`가 아니라 `기뻤어`인 이유: 컴포저의 작성자 태그 첫 칸이 이미
`좋았어`다. 한 화면에서 두 컨트롤이 같은 말을 쓰면 사용자는 둘이 같은 것인지 배워야 한다.
