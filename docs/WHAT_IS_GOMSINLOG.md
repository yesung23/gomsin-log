# 곰신로그가 무엇인가

> **이 문서 하나만 읽어도 이 제품을 이해할 수 있게 쓴다.** 처음 오는 사람 — 새 AI,
> 새 팀원, 디자이너, 투자자 — 이 20분 안에 "이게 무엇이고 왜 이렇게 생겼는가"를
> 아는 것이 목표다.
>
> **여기에는 규칙이 없다.** 규칙과 사실의 주인은 따로 있고(§8), 이 문서는 그것들을
> **설명**할 뿐 복제하지 않는다. 어긋나면 언제나 그쪽이 이긴다.

---

## 1. 한 문장

**함께하지 못한 하루를 서로 이어주고, 그렇게 이어온 시간을 둘만의 기억으로 남기는
사적인 공간.**

---

## 2. 누구의 문제인가

두 사람이 사귀는데 **생활 시간이 겹치지 않는다.**

가장 선명한 초기 형태가 군 복무 커플이다. 이 앱의 두 역할 이름이 거기서 왔다.

| 역할 | 코드값 | 누구 |
|---|---|---|
| **곰신** | `gomsin` | 군대 간 사람을 기다리는 쪽 |
| **군화** | `soldier` | 군 복무 중인 쪽 |

두 사람의 하루는 이렇게 어긋난다.

```
곰신   ─────────────────────────────────  하루 종일 폰을 쓸 수 있다
군화   ██                    ██        ██  훈련·점호 사이의 짧은 틈
```

**곰신은 하루 종일 남길 수 있고, 군화는 짧은 시간에 따라잡아야 한다.** 이 비대칭이
이 제품의 거의 모든 설계 결정을 만든다.

다만 장기 정체성은 군대가 아니다. 시차가 있는 장거리 커플, 교대 근무, 유학 — **원인은
다르고 질문은 같다.** "오늘 너는 어땠어?" 를 함께 있지 않은 채로 묻는 것.

---

## 3. 하나의 루프

이 앱이 하는 일은 결국 이것 하나다.

```
가볍게 남긴다  →  상대의 놓친 하루를 본다  →  정확한 원본으로 들어간다
      ↑                                                  │
      └──────────  실제 대화로 이어진다  ←───────────────┘
```

기능을 더할지 말지는 한 질문으로 정한다.

> **"이 기능이 서로의 하루를 더 잘 이어주는가?"**

---

## 4. 화면 다섯

```
 홈        찾기       기록 남기기      일정        우리
 ●          ○            ⊕            ○           ◐
피드      찾아보기      만들기       달력       프로필
```

| 탭 | 한 문장 |
|---|---|
| **홈** | 상대의 놓친 하루를 가장 빠르게 이해하고, 지금 있었던 일을 바로 남긴다 |
| **찾기** | 쌓인 것에서 하나를 정확히 집어낸다 |
| **기록 남기기** | 장소가 아니라 **동작**이다. 누르면 컴포저가 열린다 |
| **일정** | 둘의 미래와 기다림을 관리한다 |
| **우리** | 쌓인 것을 본다. 계정·프라이버시·기기·알림은 **☰ 안**에 있다 |

지금 화면이 실제로 어떻게 생겼는지는 [`V4_AS_BUILT.md`](V4_AS_BUILT.md)가 소유한다.

## 5. 왜 인스타그램처럼 생겼는가

**이것이 이 제품을 처음 보는 사람이 가장 많이 궁금해하는 것이고, 지금까지 어디에도
제대로 적혀 있지 않았다.**

### 빌리는 것: 자리

인스타를 쓰는 사람은 **손으로 안다.** 왼쪽 끝이 홈이고, 가운데가 만들기이고, 오른쪽
끝이 자기 프로필이라는 것을. 화면을 보지 않고도 엄지가 간다.

그 기억을 그대로 쓰면 **학습 비용이 0이 된다.** 이 앱의 사용자는 이미 인스타를 하루에
수십 번 여는 사람들이다. 새 문법을 가르치는 대신 이미 아는 문법 위에 다른 내용을 얹는다.

숫자까지 빌린다 — 헤더 56px, 스토리 레일 106px, 게시물의 세로 순서(작성자 54px →
사진/글 → 액션 44px → 캡션 → 시간). **이 숫자들이 인스타를 인스타로 보이게 한다.**

### 빌리지 않는 것: 개념

> **자리는 빌리되 개념은 빌리지 않았다.**

없는 것들, 그리고 없는 이유:

| 인스타에 있는 것 | 여기 없는 이유 |
|---|---|
| 팔로워 · 친구 추천 | **이 앱에는 남이 없다.** 두 사람뿐이다 |
| 좋아요 수 · 조회 수 | 관계를 숫자로 재기 시작하면 그 숫자가 관계가 된다 |
| 본 사람 목록 · 읽음 표시 | 상대가 내 하루를 언제 봤는지는 **내가 알 일이 아니다** |
| 연속 기록(스트릭) | 남기지 않은 날을 결핍으로 만든다. 재촉하지 않는다 |
| 알고리즘 피드 · 자동 재생 | 고를 것이 없다. 시간 순이면 된다 |

그래서 인스타의 두 번째 칸(검색)도 한 번 그대로 뒀다가 **되돌렸다.** 인스타에 검색
탭이 있는 이유는 거기에 **모르는 사람들의 게시물**이 있기 때문이고, 이 앱에는 그것이
없다.

### 그리고 종이 위에 그린다

골격은 인스타지만 **그려진 재료는 공책과 펜**이다. 손으로 그린 원, 삐뚤한 사각형,
손글씨. 이유는 이것이 SNS가 아니라 **둘이 주고받는 일기장**이기 때문이다. 완벽한 원은
인쇄된 도형으로 읽히고, 인쇄된 것은 남에게 보여주는 물건이다.

시각 언어의 주인은 [`DESIGN_V2.md`](DESIGN_V2.md)다.

### 이 결정의 값

**자리를 바꾸면 빌려온 이유 자체가 사라진다.** 실제로 한 번 바꿨다가 되돌렸다 — 그
이야기는 [`V4_AS_BUILT.md`](V4_AS_BUILT.md) §6.1에 있고, 탭을 다시 옮기려는 사람은
그것을 먼저 읽어야 한다.

## 6. 이 앱이 하지 않는 것

### 제품으로서

카카오톡 대체 · 범용 메신저 · 공개 소셜 네트워크 · 군 정보 앱 · AI 관계 평가기 ·
범용 일기장.

### 원칙으로서

- **기록은 암호화되어 저장된다.** 서버는 두 사람의 글을 읽지 못한다(E2EE).
- **기계가 읽은 감정은 작성자의 것이다.** 앱이 하루를 분석해 상대에게 알려 주지 않는다.
- **앱은 한쪽에게 다른 쪽이 "실제로 어떻게 느끼는지"를 말해 주지 않는다.** 사실과
  사용자가 고른 맥락만 보여준다.
- **없는 것은 없다고 말한다.** 기념일이 없으면 지어내 세지 않고, 상대가 아무 말도 안
  한 날에는 아무것도 띄우지 않는다 — "오늘은 신호가 없어요" 조차도. 그것 자체가
  상대가 말하지 않았다는 사실을 알리는 일이기 때문이다.

## 7. 길게 보면 무엇이 되는가

쌓인 시간이 **손에 잡히는 물건**이 된다.

```
일상 연속성 → 사적 기억 아카이브 → 암호화 미디어 → 기억 큐레이션
→ Book Studio → 선택한 기억의 실물 제품
```

이것은 다른 사업으로 갈아타는 것이 아니다. 매일 이어 온 하루가 시간이 지나 표현되는
방식이다. 사업 쪽 사실은 [`BUSINESS_MEMORY_ROADMAP_V1.md`](BUSINESS_MEMORY_ROADMAP_V1.md)가
소유한다.

## 8. 무엇이 어디의 사실인가

이 저장소는 **하나의 사실에 하나의 주인**을 둔다. 이 문서는 아무것도 소유하지 않는다.

| 질문 | 주인 |
|---|---|
| 제품 의도 · North Star · 비목표 | [`PRODUCT_V3.md`](PRODUCT_V3.md) |
| 지금 화면이 실제로 어떻게 생겼나 | [`V4_AS_BUILT.md`](V4_AS_BUILT.md) |
| 사업 · 수익화 · 시장 · 기억상품 | [`BUSINESS_MEMORY_ROADMAP_V1.md`](BUSINESS_MEMORY_ROADMAP_V1.md) |
| 시각 언어 | [`DESIGN_V2.md`](DESIGN_V2.md) |
| 구현 순서 · 단계 · 게이트 | [`ENGINEERING_ROADMAP.md`](ENGINEERING_ROADMAP.md) |
| 지금 저장소의 결함 · 미구현 | [`CURRENT_STATE.md`](CURRENT_STATE.md) |
| 남은 일 | [`V4_BACKLOG.md`](V4_BACKLOG.md) |
| 세션 작업 이력 | [`WORK_LOG.md`](WORK_LOG.md) |
| 암호 프로토콜 | [`E2EE_PHASE_1A_ARCHITECTURE_V2_1.md`](E2EE_PHASE_1A_ARCHITECTURE_V2_1.md) |
| 마이그레이션 적용 상태 | [`../supabase/migrations/README.md`](../supabase/migrations/README.md) |
| 작업 규칙 · 세션 절차 | [`../CLAUDE.md`](../CLAUDE.md) |

**문서와 코드가 어긋나면 코드가 이긴다.** 문서에 적힌 PR 번호·SHA·배포 상태는
그때의 기록일 뿐이며, 작업 시점에 다시 확인한다.

## 9. 20분 오리엔테이션

처음 오는 사람이 이 순서로 하면 된다.

```bash
# 1. 지금 상태를 기계에서 직접 읽는다 (문서가 아니라)
bash scripts/agent/session-start.sh

# 2. 돌려 본다
npm install && npm run dev

# 3. 초록인지 본다
npm run verify
```

읽는 순서: **이 문서 → [`V4_AS_BUILT.md`](V4_AS_BUILT.md)(화면) →
[`PRODUCT_V3.md`](PRODUCT_V3.md)(의도) → [`V4_BACKLOG.md`](V4_BACKLOG.md)(남은 일)**.

`PRODUCT_V3.md`는 길고 규칙으로 쓰여 있다. **처음부터 끝까지 읽지 말고** 지금 하려는
일과 관련된 절만 찾아 읽는다.

## 10. 지금 어디까지 와 있나

> 이 절만 빨리 낡는다. 숫자가 아니라 **성격**만 적고, 정확한 상태는
> [`CURRENT_STATE.md`](CURRENT_STATE.md)와 [`V4_BACKLOG.md`](V4_BACKLOG.md)에서 본다.

- **화면은 V4로 다시 지어져 프로덕션에 올라가 있다.** 인스타 골격 + 종이.
- **핵심 루프는 돈다.** 남기기 · 상대의 하루 · 원본 · 이야기거리 · 통화 모드.
- **E2EE는 테이블까지 운영에 적용됐고**, 기기에서 `기록 보호`를 켜야 실제로 암호화된다.
- **아직 없는 것:** 반응(공감·토닥이기), 일기장 지면 만들기의 클라이언트,
  결제와 실물 제작, 알림의 외부 자격증명.
