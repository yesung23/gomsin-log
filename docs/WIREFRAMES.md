# 와이어프레임 — 통화 전 60초 중심

기준: 세로형 모바일 390~430px. 일정과 여행보다 `기록 → 통화 준비`를 먼저 설계한다.

## 1. 군화 홈

```text
┌──────────────────────────────────┐
│ 곰신로그                  ＋ ⚙  │
│ 안녕, 민준 ♥                    │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 설명은 짧게, 대화는 깊게     │ │
│ │ ⏱ 통화 전 60초   새 소식 4개 │ │
│ │                              │ │
│ │ 먼저 알아둘 마음              │ │
│ │ 힘든 순간이 있었어요.         │ │
│ │ 먼저 지금 상태를 물어봐 주세요│ │
│ │                              │ │
│ │ ① 8/6 14:20                 │ │
│ │   팀 과제가 갑자기 바뀌었어   │ │
│ │ ② 8/7 12:10                 │ │
│ │   점심 먹다가 네 생각났어     │ │
│ │ ③ 8/7 18:40                 │ │
│ │   오늘 일이 정말 힘들었어     │ │
│ │                              │ │
│ │ 첫마디                        │ │
│ │ “그 일, 지금은 좀 괜찮아?”    │ │
│ │                              │ │
│ │ [통화했어요 · 여기까지 확인]  │ │
│ └──────────────────────────────┘ │
│                                  │
│ 상대의 오늘 · 감정 흐름 · 일정  │
│                                  │
│  홈   기록   일정   우리   마이  │
└──────────────────────────────────┘
```

### 결정

- 통화 브리핑은 편집 가능한 위젯이 아니라 군화 홈의 고정 핵심 영역이다.
- 핵심 맥락은 3개를 넘지 않는다.
- 발췌를 누르면 원문으로 이동한다.
- `첫마디`는 조언이 아니라 실제 기록을 바탕으로 한 열린 질문이다.

## 2. 새 소식이 없는 군화 홈

```text
┌──────────────────────────────────┐
│ ⏱ 통화 전 60초                  │
│                                  │
│              ✓                   │
│ 지난 통화 이후 새 맥락이 없어요 │
│ 바로 안부를 묻고 목소리에        │
│ 집중해도 좋아요.                 │
│                                  │
│        [최근 7일 다시 보기]      │
└──────────────────────────────────┘
```

새 소식이 없다는 상태도 유용한 정보다. 사용자를 더 읽게 만들기 위한 가짜 추천이나 질문을 채우지 않는다.

## 3. 곰신 기록 작성

```text
┌──────────────────────────────────┐

│                                  │

│                                  │

│ │ 순간 남기기                   │ │
│ │                              │ │
│ │ 무슨 일이 있었는지 ·          │ │
│ │ 어떤 마음이었는지 ·           │ │
│ │ 통화 때 듣고 싶은 말을 남겨요 │ │
│ │                              │ │
│ │ [오늘 팀 과제가 바뀌어서     ]│ │
│ │ [당황했고 네 얘기를 듣고 싶어]│ │

```

### 다음 단계 시안

저장 버튼 위에 하나의 선택만 추가한다.

```text
□ 통화 때 꼭 얘기하고 싶어
   ○ 그냥 들어줘  ○ 같이 생각해줘  ○ 답이 궁금해
```

사용자 검증 전에는 DB 필드와 화면을 추가하지 않고 현재 안내 문구로 먼저 행동 변화를 확인한다.

## 4. 원문으로 이동

```text
┌──────────────────────────────────┐
│ ‹ 기록                           │
│                                  │
│ 8월 7일                          │
│                                  │
│ ┃ 18:40  힘들었어                │
│ ┃ 오늘 일이 정말 힘들었어.       │
│ ┃ 퇴근하고 나니 조금 나아졌어.   │
│ ┃                                │
│ ┃ 브리핑에서 확인한 기록          │
│                                  │
│ 이전·다음 기록                    │
└──────────────────────────────────┘
```

브리핑은 원문을 대체하지 않는다. 발췌와 원문의 연결이 신뢰를 만든다.

## 5. 통화 후 체크포인트

```text
┌──────────────────────────────────┐
│ 통화했어요                        │
│                                  │
│ 여기까지 나눈 것으로 표시할까요? │
│ 다음에는 이후의 새 맥락부터      │
│ 보여드릴게요.                     │
│                                  │
│       [취소]  [여기까지 확인]     │
└──────────────────────────────────┘
```

현재 구현은 바로 체크하며, 파일럿에서 실수 빈도가 높으면 확인창을 추가한다.

## 6. 일정·여행 보조 화면

기존 일정·여행 와이어프레임은 유지하되 홈의 중심에서 분리한다.

- 일정: 공동 사실을 한눈에 확인
- 여행: 함께 결정한 장소와 순서를 실행
- 브리핑: 24시간 안의 중요한 일정 또는 `결정 필요` 항목만 선택적으로 연결

## 7. 반응형·접근성

- 320px에서도 제목·새 소식 수가 겹치지 않게 줄바꿈한다.
- 모든 기록 행은 최소 52px, 주요 버튼은 최소 44px다.
- 번호, 텍스트, 모양을 함께 사용하여 색상만으로 중요도를 표시하지 않는다.
- 긴 발췌는 82자 이하로 줄이고 원문에서 전체를 확인한다.
- 밝은·어두운 모드 모두 기존 코랄과 인디고 토큰을 사용한다.
- 화면 읽기 도구는 `상대의 통화 전 핵심 맥락, 3개`처럼 목록 목적과 개수를 읽는다.

## 8. Claude Design 전달 프롬프트

```text
곰신로그를 일반적인 커플 다이어리나 일정 앱처럼 디자인하지 마세요.

핵심 가치는 다음과 같습니다.
상대적으로 기록할 시간이 있는 곰신이 비동기로 하루의 맥락을 남기고,
휴대전화 사용 시간이 제한된 군화가 통화 전 60초 안에 그 맥락을 파악하여,
짧은 통화에서 상황 설명보다 질문·공감·애정 표현에 더 많은 시간을 쓰게 합니다.

반드시 먼저 설계할 화면:
1. 군화 홈의 고정 `통화 전 60초`
2. 새 소식이 없는 상태
3. 곰신의 빠른 기록 작성
4. 브리핑 발췌에서 원문으로 이동한 상태
5. 통화 후 체크포인트

디자인 원칙:
- 군화 화면은 60초 안에 읽을 수 있도록 핵심 맥락을 최대 3개만 표시합니다.
- 긴 타임라인, 점수, 감정 퍼센트, 장식용 통계를 첫 화면에 두지 마세요.
- `먼저 알아둘 마음 → 실제 맥락 → 첫마디 → 통화 완료` 순서를 유지하세요.
- 첫마디는 실제 기록 발췌에 근거한 열린 질문으로 표현하세요.
- 곰신 입력은 복잡한 설문이 아니라 글·사진·음성을 빠르게 남기는 경험이어야 합니다.
- 비공개 기록이 브리핑에 나타나는 것처럼 표현하지 마세요.
- 일정과 여행은 핵심 홈이 아니라 필요할 때 들어가는 보조 기능으로 두세요.
- 기존 따뜻한 코랄, Pretendard, 둥근 카드, 5개 하단 탭, 다크 모드를 유지하세요.
- 390px, 412px, 430px와 최소 44px 터치 영역을 지키세요.
- 시각 변경과 기능 변경을 분리해서 제시하세요.

성공한 디자인은 기능이 많아 보이는 화면이 아니라,
군화가 무엇을 물어볼지 알고 곰신이 이미 이해받았다고 느끼는 화면입니다.
```
