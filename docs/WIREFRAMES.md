# 곰신로그 디자인 방향과 전체 와이어프레임

> 핵심 화면의 최신 우선순위와 IA는 `PRODUCT_PRD.md` v5가 기준이다. 이 문서는
> 세부 화면 상태와 보조 화면 와이어프레임을 확장한다.

## 1. 추천 디자인: 깨끗한 커플 타임라인 + 컴팩트한 생활 플래너

곰신로그는 연애 감성 다이어리만도, 업무용 일정 앱만도 아니어야 한다. **실제 기록은 사진과 원문 중심으로, 통화 준비는 짧고 명확하게, 계획은 시간표처럼 실용적으로** 보여주는 것이 가장 알맞다.

시각 참고: [`design-references/clean-couple-ui-reference.jpg`](design-references/clean-couple-ui-reference.jpg). 브랜드·캐릭터·문구를 복제하지 않고 다음만 참고한다.

- 짧고 컴팩트한 상단 헤더
- 한 화면에서 여러 정보를 읽을 수 있는 균형 잡힌 밀도
- 사진·시간·원문이 이어지는 기록 타임라인
- 카드보다 여백과 얇은 구분선을 우선하는 리스트
- 코랄 주요 행동 하나와 절제된 파스텔 틴트
- 작아 보이는 컨트롤에도 충분한 숨은 터치 영역을 주는 iOS식 조작감

### 시각 언어

- 거의 흰색인 따뜻한 배경과 흰 표면, 딥 네이비 본문
- 코랄: 관계, 기록, 화면의 유일한 주요 행동
- 블루: 일정, 여행, 공동 계획
- 민트: 완료, 동기화 성공, 준비됨
- 옐로: 나만 보기, OCR 확인 필요, 지연
- 빨강: 오류와 삭제만
- 파스텔은 작은 배지·선택 상태·약한 섹션 배경에만 사용
- 카드 모서리 14~18px, 얇은 테두리, 그림자 거의 없음
- Pretendard의 읽기 쉬운 본문과 컴팩트한 제목. 화면 제목 20~22px, 섹션 제목 16~18px, 핵심 본문 15~16px, 일반 본문 14~15px, 메타 12~13px

### 피해야 할 디자인

- 첫 화면에 통계와 카드가 가득한 대시보드
- 접근성을 이유로 모든 글자·버튼·카드를 크게 만든 시니어 모드 같은 화면
- 모든 정보를 비슷한 크기의 둥근 카드로 감싼 AI 템플릿 같은 화면
- 사랑의 정도를 점수·그래프·연속 출석으로 평가하는 화면
- 모든 버튼에 서로 다른 색을 쓰는 화면
- 긴 AI 요약이 원문보다 앞서는 화면
- 기록마다 앱이 만든 제목·추천·감정 배지를 붙여 실제 사진과 사용자 문장을 가리는 화면
- 의미 없는 그라데이션, 반복되는 하트·이모지, 넓은 빈 공간
- 군화가 짧은 시간에 여러 단계의 양식을 채워야 하는 흐름

## 2. 정보 구조

```text
하단 탐색
├─ 홈: 지금 역할에 가장 중요한 행동
├─ 기록: 날짜와 미디어로 하루·추억 탐색
├─ 일정
│  ├─ 캘린더·공동 할 일
│  └─ 여행 목록·여행 상세
├─ 우리: 관계·기념일·다가오는 여행
└─ 마이
   ├─ 복무 현황·D-Day
   └─ 설정·연결·데이터·계정
```

## 3. 역할별 홈

### 곰신 홈 — 남기기 먼저

```text
┌─────────────────────────────┐
│ ♡ 곰신로그             알림 │
│ 안녕, 민지야                 │
│                             │
│ 오늘 어떤 순간이 있었나요?  │
│ [글] [사진·영상] [음성] [반응]│
│ 어제 이어 쓰던 글이 있어요 ›│
│                             │
│ 오늘 둘이 남긴 순간      3  │
│ 09:20  [사진] 출근길에 비 왔어│
│ 18:10  현우 · 오늘 훈련 끝! │
│ 20:05  [음성 0:14]          │
│                             │
│ 전역까지  D-142  ━━━━━ 68% │
└─────────────────────────────┘
 홈     기록     일정     우리     마이
```

판단: 홈에 긴 입력 폼을 펼치지 않는다. 기록 방식을 먼저 고르고 필요한 입력만 이어서 보여주며, 공개 범위와 통화 표시는 저장 직전에 확인한다. 타일은 시각적으로 컴팩트하되 행과 여백을 포함한 실제 터치 영역은 44px 이상이다.

### 군화 홈 — 60초 따라잡기 먼저

```text
┌─────────────────────────────┐
│ ♡ 곰신로그             21:10│
│ 오늘 통화 전, 이것만 봐요   │
│                             │
│ 통화 전 60초 · 3건          │
│ 먼저 살필 마음 · 많이 지침  │
│ • 꼭 얘기  과제가 바뀌었어  │
│ • 힘들었어 점심에 울컥했어  │
│ • 결정 필요 제주 숙소 고르기│
│ 첫마디 “그 뒤엔 괜찮아졌어?”│
│ [더 보기]      [여기까지 확인]│
│                             │
│ 상대방의 오늘          전체 ›│
│ 09:20 [사진] 출근길에 비 왔어│
│ 12:10 [음성] 네 생각났어    │
│                             │
│ 전역까지  D-142  ━━━━━ 68% │
└─────────────────────────────┘
 홈     기록     일정     우리     마이
```

판단: 통화 준비는 최대 3건으로 끝낸다. 브리핑은 텍스트 판단, 타임라인은 실제 사진·음성·원문으로 시각 문법을 분리한다. 브리핑 카드가 화면을 독점하지 않고 390×844 첫 화면에 확인 행동과 실제 기록 일부가 함께 보여야 한다.

## 5. 기록 모아보기와 상세

```text
┌─────────────────────────────┐
│ 기록                    달력│
│ [전체] [꼭 얘기] [사진] [음성]│
│ 8월 8일 토요일              │
│                             │
│ 08:12  [사진]  민지         │
│         오늘 날씨가 정말 좋다│
│         꼭 얘기          ♡  │
│                             │
│ 12:41  [사진]  민지         │
│         맛있는 점심 먹었어! │
│                             │
│ 17:18  [음성 0:14]  현우    │
│         오늘 하루도 고생했어│
│                             │
│        [+ 지금의 마음 남기기]│
└─────────────────────────────┘
```

시간은 왼쪽, 미디어 썸네일은 가운데, 작성자·원문·상태는 오른쪽에 둔다. 개별 기록을 큰 카드로 감싸지 않고 여백과 얇은 구분선으로 날짜의 흐름을 만든다. 앱이 만든 제목이나 감정 해석은 원문보다 앞에 놓지 않는다. 작성자는 이름·위치·아이콘·약한 틴트를 함께 사용해 구분하고, 상세에서는 본인 기록에만 수정·삭제를 노출한다.

## 6. 일정과 공동 할 일

```text
┌─────────────────────────────┐
│ [일정]  여행                 │
│ 2026년 8월              +   │
│ ‹  일 월 화 수 목 금 토   › │
│          6  7 [8] 9 10     │
├─────────────────────────────┤
│ 8월 8일                     │
│ 14:00  면회 · 함께           │
│ 19:00  숙소 예약 마감        │
├─────────────────────────────┤
│ 같이 할 일                  │
│ ○ 신분증 챙기기 · 군화       │
│ ● 숙소 예약 · 함께           │
│ [할 일 빠르게 추가…]        │
└─────────────────────────────┘
```

날짜 선택 뒤 일정과 할 일을 한 화면에서 본다. 색은 일정 유형을 보조할 뿐 제목·시각·담당자 텍스트를 대체하지 않는다.

일정 하나마다 큰 카드를 만들지 않는다. 날짜 단위의 한 표면 안에서 시간순 리스트와 얇은 구분선을 사용한다.

## 7. 여행 목록과 상세

```text
┌─────────────────────────────┐
│ 일정  [여행]            +   │
│ 다가오는 여행                │
│ 제주도 · 8/20–8/22 · 계획 중│
│ 부산 · 9/14–9/15 · 계획 중  │
└─────────────────────────────┘

┌─────────────────────────────┐
│ ‹ 제주도 여행          편집  │
│ 8/20 수  [8/21 목]  8/22 금 │
├─────────────────────────────┤
│ 10:00  성산일출봉            │
│         07:30–20:00 · 활동   │
│ 12:30  해녀의 집             │
│         11:00–19:00 · 맛집   │
│ 미정    오션뷰 카페      ↑ ↓ │
│                             │
│ [+ 직접 추가] [지도 캡처]   │
├─────────────────────────────┤
│ 같이 준비                    │
│ ● 렌터카 예약  ○ 우산 챙기기│
│ [여행 기간 추억 보기]       │
└─────────────────────────────┘
```

지도 자체보다 **날짜·시간·순서**가 우선이다. 캡처 OCR은 입력을 줄이는 보조 수단이며 저장 전에 확인 화면을 둔다.

장소 하나마다 독립 카드나 강한 색을 붙이지 않는다. 시간, 장소명, 영업시간, 확인 필요 상태를 한 행 안에서 읽고, 위/아래 조작은 작게 보여도 행 전체 기준 44px 터치 영역을 확보한다.

## 9. 설정과 위험 행동

설정은 `내 정보 → 커플 연결 → 기능 바로가기 → 데이터 → 법적 문서 → 위험 행동` 순서다. 연결 해제·기록 전체 삭제·계정 삭제는 페이지 맨 아래 별도 영역에 두고 결과를 자연어로 먼저 설명한다.

```text
┌─────────────────────────────┐
│ 계정을 삭제할까요?           │
│ 내 기록과 계정 접근이 ...    │
│ 삭제 대기 기간에는 취소하여  │
│ 복구할 수 있어요.            │
│ [취소]      [삭제 요청]      │
└─────────────────────────────┘
```

## 10. 상태 디자인

- 빈 상태: “없음”만 쓰지 말고 왜 비었는지와 다음 행동 하나 제공
- 저장 중: 버튼 중복 실행 차단, 입력 내용 유지
- 오프라인: 상단의 조용한 상태 띠 + 기능별 가능/불가능 설명
- 오류: 원인, 잃지 않은 데이터, 재시도 행동을 함께 표시
- 동기화 지연: 빈 화면 대신 “확인 중”으로 표시
- 접근 거부: 데이터 존재를 암시하지 않는 일반 안내

## 11. 반응형·접근성

- 기준 폭 390–430px, 최소 320px; 태블릿/데스크톱은 중앙 콘텐츠 폭을 제한
- 본문은 기본 14~16px 범위에서 위계를 만들고, 지나치게 큰 제목과 버튼으로 정보량을 줄이지 않음
- 시각적 컨트롤은 컴팩트하게 보이되 주요 터치 영역 44px 이상을 투명 패딩·행 전체 클릭으로 확보
- 키보드로 카드 열기·순서 변경·모달 닫기 가능
- 포커스를 숨기지 않고 화면 이동을 보조기기에 알림
- 사진 대체 텍스트, 음성/영상의 종류·재생 상태를 텍스트로 제공
- 밝은/어두운 테마 모두 동일한 정보 위계와 대비 유지

## 12. 디자인 검토 질문

각 화면을 만들거나 수정할 때 아래 여덟 질문을 통과해야 한다.

1. 이 역할의 사용자가 지금 가장 먼저 해야 할 일이 첫눈에 보이는가?
2. 군화가 60초 안에 읽을 수 있고 한 손으로 조작할 수 있는가?
3. 곰신이 “또 길게 설명해야 한다”는 부담 없이 남길 수 있는가?
4. 둘의 민감한 정보와 비공개 선택이 눈에 보이고 실제 권한과 일치하는가?
5. 이 기능이 통화를 대체하지 않고 더 좋은 대화를 준비하는가?
6. 실제 사진·음성·사용자 원문이 앱의 설명·배지·AI식 요약보다 먼저 보이는가?
7. 카드와 빈 공간을 줄인 결과 한 화면에 필요한 정보가 자연스럽게 들어오는가?
8. 젊고 정돈된 커플 앱으로 보이며 시니어 모드·업무 대시보드·AI 템플릿처럼 보이지 않는가?
