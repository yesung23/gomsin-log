# 2계정 수동 테스트 (비개발자용)

앱의 핵심은 **두 사람이 서로 연결된 비공개 공간**입니다. 이건 혼자서는 확인할 수
없어서, 계정 2개로 직접 해 봐야 합니다.

> ✅ 자동 테스트 152개 / 21개 파일이 통과하지만, 그건 **코드 논리**만 검증합니다.
> 실제 Supabase 서버에 대한 검증은 아래를 사람이 직접 해야만 확인됩니다.
> **아직 실행되지 않았습니다.**

---

## 준비

- 이메일 계정 2개 (또는 구글 계정 2개)
- 기기/브라우저 2개
  - 같은 컴퓨터라면 **일반 창 + 시크릿 창** 으로도 됩니다.
  - 더 정확히 하려면 **다른 브라우저**(크롬 + 파이어폭스)를 쓰세요.
- 아래에서 A = 곰신 역할, B = 군화 역할

각 항목은 **기대 결과가 나오면 ✅, 다르면 ❌ 와 무슨 일이 났는지** 적으세요.

### 5-5. 마이그레이션 015 확인 (staging에서 필수)

015가 고친 문제들은 **한 번 잘못되면 조용히 넘어가기 쉬운** 것들입니다.
아래는 정적 검토로 확정할 수 없어 실제 두 계정으로만 확인 가능한 항목입니다.

| # | 하는 일 | 기대 결과 | 결과 |
|---|---|---|---|
| 5-5-1 | **A가 "나만 보기" 일정을 삭제.** 그동안 B 화면을 그대로 보고 있기 | B 화면에 **아무 변화도 없어야 함**. 목록이 다시 불러와지는 깜빡임조차 없어야 합니다 | |
| 5-5-2 | A가 **공유** 일정을 삭제 | B 화면에서 몇 초 안에 사라짐 (5-5-1과 대비되어야 함) | |
| 5-5-3 | 여행 하루에 항목 3개를 만들고 **1번과 2번의 순서를 바꾸기** | 오류 없이 저장되고 순서가 유지됨 | |
| 5-5-4 | 여행 항목의 **제목만** 수정해 저장 | 성공. "순서는 reorder로만 바꿀 수 있다"는 오류가 나오면 ❌ | |
| 5-5-5 | B가 5-5-3의 순서를 바꾼 직후, A가 (갱신 전 화면에서) 같은 항목의 제목 수정 | 성공해야 함 (오래된 순서 값 때문에 실패하면 ❌) | |
