# Native release guide (Android / iOS)

Scope: the two Capacitor shells that wrap the same web bundle. This is the
reference for the decisions encoded in `android/` and `ios/`, what is proven
automatically, and what can only be proven on hardware.

Nothing in this repository is signed, and nothing in it can be signed. There is
no keystore, no certificate, no provisioning profile, no App Store Connect API
key and no password. Release signing happens on a maintainer's machine or via
Play App Signing, using material that never enters version control.

---

## 1. Source-of-truth decision: `android/` and `ios/` are TRACKED

Both native projects are committed to git. The same strategy is applied to both;
neither is regenerated by `cap add` as part of a build.

### Why

* **A permission is a review surface.** `AndroidManifest.xml`,
  `App.entitlements`, `Info.plist` and `PrivacyInfo.xcprivacy` decide what the OS
  lets the app reach and what the store believes about it. If those files only
  exist on one maintainer's disk after they run a generator, nobody can review a
  diff of them. Tracking them makes "we added `RECORD_AUDIO`" and "we stopped
  excluding diary data from device transfer" appear in a pull request.
* **`cap add` reverts hardening silently.** It writes a template: `allowBackup`
  defaulted, no `dataExtractionRules`, no network security config, a deep-link
  filter built from `@string/custom_url_scheme`, and Capacitor's own logo. Every
  hardening decision in section 3 and 4 would have to be reapplied by hand after
  each regeneration, and a missed one fails open.
* **The reproducibility argument cuts the other way.** `cap sync` *is* the
  generator — for the parts that are genuinely generated (see below). Everything
  it writes is ignored, so a clean clone plus `npm ci && npm run build &&
  npx cap sync` reproduces a byte-identical native configuration. Tracking the
  hand-authored files and generating the derived ones is what makes that true.

### Cost, accepted deliberately

* Upgrading Capacitor is a manual merge: `npx cap sync` will not update
  `build.gradle`, the manifest or the Xcode project. The upgrade procedure is to
  regenerate into a scratch directory (`npx cap add android` in a clone), diff it
  against the tracked project, and port template changes by hand. That is more
  work than deleting and recreating, and it is the price of reviewability.
* The tracked tree carries ~77 files of native project, including
  `gradle-wrapper.jar` and generated splash/icon PNGs. Those PNGs are outputs of
  `scripts/assets/generate-app-assets.mjs`; they are tracked because Gradle and
  Xcode need them present at build time and because a store icon changing is
  something a reviewer should see.

### What is generated, not tracked

Regenerated deterministically by `npx cap sync <platform>` from
`capacitor.config.ts`, `package.json` and `dist/`, and ignored in git:

| Path | Written by |
| --- | --- |
| `android/app/src/main/assets/public/` | `cap copy` (the web bundle) |
| `android/app/src/main/assets/capacitor.config.json` | `cap copy` |
| `android/app/src/main/assets/capacitor.plugins.json` | `cap update` |
| `android/app/src/main/res/xml/config.xml` | `cap copy` |
| `android/capacitor-cordova-android-plugins/` | `cap update` |
| `ios/App/App/public/` | `cap copy` |
| `ios/App/App/capacitor.config.json`, `config.xml` | `cap copy` |
| `ios/capacitor-cordova-ios-plugins/` | `cap update` |
| `ios/App/Pods/` | `pod install` |

`ios/App/Podfile.lock` **is** tracked: all four pods are local `:path`
references into `node_modules`, so the lock is a pure function of
`package-lock.json` and pins the podspec checksums the release was built from.

### Proving a clean clone reproduces the same configuration

```bash
git clone <repo> fresh && cd fresh && git checkout <sha>
npm ci
VITE_SUPABASE_URL=https://example.supabase.co \
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_test_public_key_not_a_secret npm run build
npx cap sync android
npx cap sync ios
npm run verify:assets
git status --porcelain   # must be empty
```

`git status` being empty is the native-sync claim. Asset 검증은
`scripts/assets/app-assets.manifest.json`에 기록된 SVG·생성기 해시와 각 PNG의
크기·알파 형식·디코딩된 RGBA 픽셀 지문을 비교합니다. CI에서 SVG를 다시 렌더링하지
않는 이유는 같은 SVG도 macOS와 Linux의 librsvg/libvips 조합에 따라 경계 픽셀이
달라질 수 있기 때문입니다. CI runs this
(`native-release-validation.yml`, jobs `capacitor-sync-reproducibility` and
`generated-file-cleanliness`).

## 2. Version and build-number procedure

One marketing version, two build counters. `package.json` `version` is the
source of truth for the marketing version and both platforms must agree with it;
`src/lib/nativeConfig.test.ts` fails the build if they drift.

| Value | Android | iOS | Rule |
| --- | --- | --- | --- |
| Marketing version | `versionName` in `android/app/build.gradle` | `MARKETING_VERSION` in `project.pbxproj` (`CFBundleShortVersionString` reads it) | Must equal `package.json` `version`. |
| Build number | `versionCode` (integer) | `CURRENT_PROJECT_VERSION` (`CFBundleVersion` reads it) | Monotonically increasing. Bumped on EVERY upload, including a re-upload of an unchanged marketing version. Never reused, never lowered. |

Release steps:

1. Bump `version` in `package.json`.
2. Set `versionName` to the same string; increment `versionCode` by one.
3. Set `MARKETING_VERSION` to the same string; increment
   `CURRENT_PROJECT_VERSION` by one.
4. `npm run verify` then `npm run verify:native`.
5. Android: `npm run cap:assemble` produces an **unsigned** `bundleRelease`
   artifact. Sign it locally or let Play App Signing do it.
6. iOS: archive from Xcode on macOS with a real team and profile. Neither the
   team id nor the profile is in this repository.

`versionCode` and `CURRENT_PROJECT_VERSION` are independent counters; they are
not expected to match each other.

## 3. Android decisions

| Property | Value | Why |
| --- | --- | --- |
| `applicationId` | `app.gomsinlog` | Immutable after the first Play release. |
| Label | `곰신로그` (`app_name`, `title_activity_main`) | Korean-only product. |
| Deep link | one VIEW filter, `scheme=gomsinlog` `host=auth` `path=/callback` | Exact-match path. A scheme-only filter would claim every `gomsinlog://` URL from any app or web page and hand it to the OAuth token exchange. |
| Permissions | `INTERNET`, `ACCESS_NETWORK_STATE`, `POST_NOTIFICATIONS` | `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS` are deliberately undeclared while voice recording/upload is inactive until P6. See below. |
| `android:exported` | explicit on every component | Required from API 31, and explicit beats inherited. |
| `allowBackup` | `false`, plus `backup_rules.xml` and `data_extraction_rules.xml` excluding everything from cloud backup AND device transfer | A phone backup or a device-to-device transfer must not be a plaintext copy of a private diary. Cost: moving phones means signing in again and re-syncing from Supabase. |
| Network security | `usesCleartextTraffic="false"`, `network_security_config.xml` with `<certificates src="system" />` only | Everything is https/wss. Omitting the user store means an MDM- or user-installed root cannot terminate TLS for this app. Cost: debugging traffic with mitmproxy needs a temporary debug-only override. |
| WebView debugging | `webContentsDebuggingEnabled: false` in `capacitor.config.ts`, `debuggable false` in the release build type | Capacitor otherwise derives this from `FLAG_DEBUGGABLE`. With remote debugging on, any process that can reach adb can read the DOM and `localStorage`. |
| R8 / resource shrinking | OFF for v1 | The bridge resolves plugins reflectively from `capacitor.plugins.json`; keep rules can only be proven on a device or emulator, and neither exists in this environment. Turning it on unverified risks a release-only "plugin not implemented". Revisit behind the device gate. |
| Signing | none | No `signingConfig`, no keystore, no `keystore.properties`. `bundleRelease` is unsigned by design. |

### Microphone (audit item C-2)

Voice recording and voice note upload in the composer are currently **inactive**
until P6 (photo-only upload gate). Existing voice attachment playback and past
audio records remain supported, but no code calls `getUserMedia({ audio: true })`
in the active composer path.

An unused microphone permission in the store binary is a review and privacy audit
flag. Therefore, `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS` are deliberately
**not declared** in `AndroidManifest.xml`, and `NSMicrophoneUsageDescription` is
**deliberately absent** in `Info.plist` until P6 re-admits voice recording.

When voice recording is re-admitted at P6 using Web `getUserMedia` +
`MediaRecorder`, Capacitor routes that through `WebChromeClient.onPermissionRequest`
(`AUDIO_CAPTURE`) on Android and `requestMediaCapturePermissionFor` on iOS, which
will require restoring the permissions.

The user-facing strings in `src/lib/nativePermissions.ts` (`MICROPHONE_RATIONALE`
and `microphoneDeniedMessage()`) remain parked for that future release.

### Camera (audit item H-2)

**Decision: keep `capture="environment"`, do NOT declare `android.permission.CAMERA`.**

`지금찍기` sets `capture="environment"` on the file input.
`BridgeWebChromeClient.onShowFileChooser` handles that by launching
`MediaStore.ACTION_IMAGE_CAPTURE` — the *system camera app* takes the photo and
returns a `content://` URI; this process never opens the camera device. And
`isMediaCaptureSupported()` (same file, lines 307–313) treats "CAMERA is not
declared at all" as permitted:

```java
return PermissionHelper.hasPermissions(context, {CAMERA})
    || !PermissionHelper.hasDefinedPermission(context, CAMERA);
```

So declaring `CAMERA` would **add** a runtime prompt and remove nothing. The
alternative — dropping `capture` — would make `지금찍기` and `사진·영상` the same
button, a product regression, and would not improve the permission set. Not
declared, deliberately, and `NativeConfigTest` fails if it reappears.

The accept list is `image/*` only for this button. With `video/*` also present
Capacitor prefers `ACTION_VIDEO_CAPTURE`, so "take a photo now" opened a
camcorder.

On **iOS** the same attribute is handled differently: WKWebView presents the
camera in-process, which does require `NSCameraUsageDescription`. That key exists
for exactly this reason and `src/lib/nativeConfig.test.ts` ties the two together
— remove `capture` and the test demands the key be removed with it.

### File-picker gesture safety (audit item H-3)

`input.click()` now runs in the same task as the tap. It used to sit inside
`setTimeout(…, 50)`, which moves the click into a later macrotask and outside the
transient user activation the gesture created; Chrome tolerates that, Android
WebView and WKWebView gate file choosers more strictly and the picker never
appeared. The delay was never needed — the file input renders unconditionally,
outside the `showInputCard` block, so the ref is already attached. A null ref now
raises a toast instead of returning silently.

`src/components/widgets/TodayLogWidgetGesture.test.tsx` asserts the click is
synchronous. **Behavioural confirmation on real Android/iOS hardware is a DEVICE
GATE** — no emulator is available here (`/dev/kvm` is absent).

## 4. iOS decisions

| Property | Value | Why |
| --- | --- | --- |
| `PRODUCT_BUNDLE_IDENTIFIER` | `app.gomsinlog` | Same id as Play; immutable. |
| `CFBundleDisplayName` | `곰신로그` | Literal UTF-8 in a file declaring `encoding="UTF-8"`. Not XML entities, not transliterated. `CFBundleDevelopmentRegion` is `ko`. |
| `CFBundleURLTypes` | one entry, scheme `gomsinlog`, `CFBundleURLName` `app.gomsinlog.auth`, `LSHandlerRank` `Owner` | iOS cannot filter a custom scheme by host or path, so `isNativeAuthCallbackUrl()` in `src/lib/platform.ts` is what makes iOS behave like the Android intent-filter. Without it any app could hand an arbitrary `gomsinlog://` URL to the token exchange. |
| `NSMicrophoneUsageDescription` | **absent** | Voice recording/upload is inactive until P6; undeclared to avoid unused permission review flags. See C-2 above. |
| `NSCameraUsageDescription` | Korean, specific | Required by the in-process capture UI that `capture="environment"` triggers. See H-2. |
| `NSPhotoLibraryUsageDescription` | **absent** | The gallery path goes through the out-of-process PHPicker / UIDocumentPicker, which returns only the chosen file and needs no library authorisation. No code reads or writes the photo library. |
| App Transport Security | `NSAppTransportSecurity` **absent** | Omission is the secure default: TLS 1.2+, forward secrecy, no arbitrary loads. Supabase is https/wss only. An empty dictionary would just invite someone to relax it. |
| `ITSAppUsesNonExemptEncryption` | `false` | Only platform TLS, which is exempt. Removes the manual question on every upload. |
| Data protection | `com.apple.developer.default-data-protection = NSFileProtectionComplete` | Container unreadable while locked. Requires the Data Protection capability on the App ID; without it, signing fails with a profile mismatch. |
| Backup exclusion | `AppDelegate.excludeLocalDataFromBackup()` marks `Library/WebKit`, `Library/Cookies`, `Library/HTTPStorages`, `Library/kvstore` `isExcludedFromBackup` | The iOS counterpart of `allowBackup=false`. Those directories hold WKWebView `localStorage` (the Supabase session and cached record state) and Capacitor's key-value store. Set at launch because the flag is a directory attribute and must precede WebKit populating it. |
| iCloud | no container, no ubiquity entitlement | Sync is Supabase only. |
| Push, Sign in with Apple entitlement, associated domains | none | `signInWithApple()` uses the same Supabase web OAuth path as Google, so no `applesignin` entitlement is required; claiming one breaks signing on profiles without the capability. |
| Signing | `CODE_SIGN_STYLE = Automatic`, no `DEVELOPMENT_TEAM`, no `PROVISIONING_PROFILE` | Nothing identifying an Apple account is committed. |

### Keychain accessibility

**Decision: Keychain use is confined to the first-party device-keys plugin, in
the app's own default access group, and no `keychain-access-groups` entitlement
is declared.**

This section previously said the app does not use the Keychain at all. That was
wrong, and wrong in the place it mattered most: it hid where the E2EE device keys
live.

The Supabase session lives in WKWebView `localStorage`, which is inside the app
container and therefore covered by `NSFileProtectionComplete` and by the backup
exclusion above. What does use the Keychain is
`packages/capacitor-device-keys/ios/Sources/DeviceKeysPlugin/`:

| File | Item | Purpose |
|---|---|---|
| `DeviceKeys.swift` | Secure Enclave P-256 key via `SecAccessControlCreateWithFlags`, falling back to a software `kSecClassKey` item | the device identity key used for E2EE bootstrap and recovery |
| `LocalKeys.swift` | `kSecClassGenericPassword` item | the local content key |

`src/lib/iosPrivacyManifest.test.ts` measures that those two files are the ONLY
Keychain callers across the Swift sources and the pods in `ios/App/Podfile`, so
the boundary cannot quietly widen.

`keychain-access-groups` is deliberately absent. Neither call site sets
`kSecAttrAccessGroup`, so both items live in the app's default access group and
are readable by this bundle alone. Declaring the entitlement would move them into
a shared group that any other bundle carrying the same entitlement could read —
for the device key, that is handing another process the material that
authenticates this device. Keep the entitlement out, and keep the plugin free of
`kSecAttrAccessGroup`.

For any NEW Keychain item, the accessibility class to use is
`kSecAttrAccessibleWhenUnlockedThisDeviceOnly` — device-only so it cannot travel
in an iCloud Keychain backup, and unlocked-only to match the container's
Complete protection. Add it explicitly at the call site; never rely on the
`kSecAttrAccessibleWhenUnlocked` default.

### Privacy manifest (`PrivacyInfo.xcprivacy`)

`NSPrivacyAccessedAPITypes` is **empty, as a measured result**. Apple's
required-reason categories are UserDefaults (CA92.1), file timestamp (C617.1),
system boot time (35F9.1), disk space (E174.1) and active keyboards (3EC4.1).
The complete iOS compile surface is:

* `ios/App/App/AppDelegate.swift` — the only first-party Swift file
* `node_modules/@capacitor/ios` — pods `Capacitor` and `CapacitorCordova`
* `node_modules/@capacitor/app/ios` — pod `CapacitorApp`
* `node_modules/@capacitor/browser/ios` — pod `CapacitorBrowser`

…which is exactly the four `pod` lines in `ios/App/Podfile`.
`src/lib/iosPrivacyManifest.test.ts` derives that list *from the Podfile* and
greps it for every symbol in the five categories. The scan is empty, and both
pods ship their own `PrivacyInfo.xcprivacy` with an empty
`NSPrivacyAccessedAPITypes`, which agrees.

`AppDelegate.swift` uses `FileManager.url(for:in:appropriateFor:create:)`,
`createDirectory` and `URL.setResourceValues(isExcludedFromBackup)`. None is a
required-reason symbol: none reads a file timestamp or queries free space.

`NSPrivacyCollectedDataTypes` declares email address, other user content,
photos/videos, audio and health (menstrual-cycle entries), all linked to the
account, none used for tracking, all for app functionality.
`NSPrivacyTracking` is false with no tracking domains: there is no analytics SDK,
no advertising identifier and no third-party network peer. EmoFlow emotion
analysis is a deterministic local rule engine
(`src/lib/emotionCandidates.ts`), not an external service.

**If a plugin is added, do not copy a declaration from a blog post.** Re-run
`npm run verify:native`, read the pod's own manifest, and declare only what the
code proves.

## 5. Assets (audit item H-1)

`scripts/assets/generate-app-assets.mjs` rasterises one source —
`public/favicon.svg` — into every raster asset the PWA and both stores need. It
uses fixed geometry and encoder settings. `npm run assets:generate` writes them;
`npm run verify:assets` verifies the source SVG and generator revision, then fails
on any committed PNG dimension, alpha-channel or decoded-pixel fingerprint
difference. Platform-specific rasterizer and PNG compression differences cannot
make CI disagree with a reviewed, committed asset.

Format rules it enforces:

| Asset | Size | Alpha | Why |
| --- | --- | --- | --- |
| `public/icons/icon-192.png`, `icon-512.png` | 192, 512 | kept (32-bit RGBA) | Play listing wants a 512×512 32-bit PNG; rounded corners are part of the mark on the web. |
| `public/icons/icon-maskable-512.png` | 512 | opaque, full bleed | Mark inside the inner safe circle so a launcher mask cannot clip it. |
| `public/icons/apple-touch-icon.png` | 180 | opaque | iOS masks corners itself and paints alpha black. |
| `ios/.../AppIcon-512@2x.png` | 1024 | **opaque** | An alpha channel is an App Store validation failure. |
| `android/.../mipmap-*/ic_launcher_foreground.png` | 108dp-proportioned | transparent | Adaptive-icon foreground layer over `@color/ic_launcher_background`. |

`public/manifest.json` declares the PNGs with `image/png`, correct `sizes`, and
`purpose` split so one icon is `maskable` and the others `any` — it previously
declared every icon as `image/svg+xml`. `public/sw.js` precaches the same list.
`src/lib/appAssets.test.ts` reads the PNG `IHDR` chunks directly and asserts the
dimensions and colour type, including that the 1024 App Store icon has no alpha.

## 7. Store submission checklist

1. `npm run verify && npm run verify:native && npm run verify:assets`.
2. Bump versions per section 2.
3. Android: `npm run cap:sync` then `cd android && ./gradlew bundleRelease`; sign
   with material that is not in this repository.
4. iOS: `npm run cap:sync:ios`, `cd ios/App && pod install`, archive in Xcode
   with a real team.
5. Register `gomsinlog://auth/callback` in the Supabase dashboard redirect URLs
   and in the Google / Apple OAuth clients.
6. Enable the **Data Protection** capability (Complete Protection) on the App ID
   before archiving, or signing fails.
7. Play Data Safety and App Store privacy answers must match
   `PrivacyInfo.xcprivacy` and `docs/privacy-access-matrix.md`.
