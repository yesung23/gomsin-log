# 사진 비용과 수익 운영 기준

기준일: 2026-09-05. 제품 결정은 [V5 §4·7·12](../PRODUCT_V5_MASTER_DECISION.md),
사업 원칙은 [사업 로드맵 §9](../BUSINESS_MEMORY_ROADMAP_V1.md)가 소유한다.
이 문서는 실행·계측 방법이며, 실제 프로젝트 비용이나 수용량의 인증서가 아니다.

## 1. 고객에게 파는 가치

| 경계 | 제공 가치 | 중단·환불 시 보존 |
|---|---|---|
| 무료 | 기록·최적화 사진·상대의 오늘·기본 정원·원본 선택·기본 내보내기 | 기록과 정상 사진 보존 |
| 1회 구매 | 권리가 확인된 액세서리·건물·종이, 디지털 책 최종 제작 | 다른 구매와 사용자 원본은 유지 |
| 선택형 Plus | 계속 갱신되는 편집 라이브러리와 고급 조판·프로젝트 관리 | 기존 기록·완성본 유지, 무료 디자인으로 초안 전환 가능 |

Plus를 서버비 명목으로 강제하지 않는다. 반복해서 제공할 가치가 실제로 동작하기 전에는
판매하지 않는다. 자동갱신 구독의 지속 가치와 상품 설명은 [Apple 심사 기준 §3.1.2](https://developer.apple.com/app-store/review/guidelines/#subscriptions)를 따른다.
디지털 상품과 실물 인쇄 주문은 결제 경로·원장을 분리한다.

앱의 `src/lib/iap/catalog.ts`에 6종 상품 식별자와 권리 유형이 있지만 모두 판매 OFF다.
StoreKit 가격·실제 상품 승인·Sandbox 검증이 없는 화면에 가짜 구매 완료를 만들지 않는다.
월 4,900원/연 39,000원은 V5의 가격 가설이지 확정 판매가가 아니다.

수익 판단은 매출이 아니라 **세금·스토어 수수료·환불 충당·고객지원·편집 콘텐츠 제작비를 뺀
기여이익**으로 한다. [Apple Small Business Program](https://developer.apple.com/app-store/small-business-program/)의
15%는 가입 자격·승인 조건이 있는 제도이며, GitHub 학생팩 또는 Apple 개발자 가입만으로
우리 계정에 적용됐다고 가정하지 않는다. 현재 계정 적용 상태는 UNVERIFIED다.

## 2. 사진의 세 가지 역할

| 종류 | 현재 구현 | 비용·품질 원칙 |
|---|---|---|
| 프로필 사진 | `profileAvatars` + migration 089 로컬 구현, 최대 256px 정사각형·64KiB JPEG·계정당 한 행 | 본인/현재 파트너만 조회, 교체본을 중복 누적하지 않음. 일반 기록 사진에는 이 DB 저장 방식을 쓰지 않음 |
| 기록용 화면 사진 | `uploadRecordMedia → sanitizePhotoForUpload`, 긴 변 2048px 이하 JPEG quality 0.84 | 기기에서 회전 반영·EXIF 제거·중립 파일명. 작은 사진을 확대하지 않음. 압축률과 평균 용량은 사진에 따라 다름 |
| 목록 thumbnail / 책 print master | 아직 앱 end-to-end 미구현 | thumbnail은 화면용과 다른 variant. print master는 정확한 선택·crop·project/order에 연결 |

2560px 화면용·640px thumbnail은 V5의 비교 대상이다. 실기기와 대표 사진 묶음 검증 없이
2048→2560을 곧바로 바꾸거나 “원본과 화질이 같다”고 광고하지 않는다. 아래 500/50KiB는
비용 민감도 계산용 가정으로, 실제 압축 측정치가 아니다.

책 사진은 구독 여부가 아니라 **사용자가 고른 정확한 원본과 인쇄 배치**로 구분한다.
crop 후 실제 픽셀 / 인쇄 인치로 PPI를 계산한다. 300 목표, 240 미만 경고, 180 미만 실물 주문
차단은 V5 기준이며 샘플 인쇄로 검증해야 한다. 기존 2048px도 작은 배치에는 충분할 수 있다.
부족한 경우만 원본을 다시 고르게 하며, 구독이 없다고 같은 사진을 저화질 처리하지 않는다.
선택된 원본의 hash, record/photo id, crop, 목적, project revision으로 연결하고 서명 URL을
원본 식별자로 쓰지 않는다. 상대 원본은 일반 공유와 별도로 제작 동의를 확인한다.
취소·만료·환불은 임시 제작 파일 수명만 정리하며 기존 기록 사진을 삭제하지 않는다.

중요한 통합 제약: 현재 Attachment는 `type/name/path`만 저장·검증하며 암호문 문서에도 같은
projection을 쓴다. thumbnail 경로를 임의 필드에 추가하면 저장 과정에서 사라지고 Storage
권한도 성립하지 않는다. 별도 variant 계약과 RLS·재시도·고아 정리를 먼저 검증해야 한다.
전체 원본 7/30일 자동 보관, 기존 사진 일괄 재압축·덮어쓰기는 하지 않는다.

## 3. 실행 가능한 비용 계산

```sh
node --test scripts/operations/media-economics.test.mjs
node scripts/operations/media-economics.mjs
```

계산은 콘텐츠/계정/비밀키 없이 집계 입력만 쓴다. 가입자 수와 동시접속 수, 저장 사진 수를
서로 대체하지 않는다. GB와 KiB 단위도 구분한다.

공개 가격은 2026-09-05 [Supabase 공식 가격표](https://supabase.com/pricing) 기준으로 고정했다.
Pro 기본 $25, 포함 Storage 100GB/초과 $0.0213/GB, 비캐시/캐시 전송 각각 250GB 포함 후
$0.09/$0.03/GB, MAU 100,000 포함 후 $0.00325를 계산한다. 실제 프로젝트 요금제는 미확인이다.

예시 가정: 1인 하루 2장, 같은 인원이 12개월 축적, 하루 목록 20회/크게 보기 2회,
master 500KiB, 가상 thumbnail 50KiB, cache hit 0%. 탈퇴/비활성 사진도 임의 삭제하지 않는다.

| 커플 수 | master만 사용: 저장/월 전송/부분 비용 | thumbnail 사용 가정: 저장/월 전송/부분 비용 |
|---|---|---|
| 100 | 73.7GB / 67.6GB / $25.00 | 81.1GB / 12.3GB / $25.00 |
| 1,000 | 737.3GB / 675.8GB / $76.90 | 811.0GB / 122.9GB / $40.14 |
| 10,000 | 7,372.8GB / 6,758.4GB / $765.67 | 8,110.1GB / 1,228.8GB / $283.71 |

이는 **가정에서 계산한 미디어·Auth 포함 부분 비용**이다. Compute 증설, DB/백업, Realtime,
Edge 초과, 이메일, 세금, CS, 콘텐츠 제작, 실물 원가가 빠져 있다. 총 서버비 또는 해당 인원
수용 보장으로 쓰지 않는다. private Storage의 캐시 적중률도 관측 전 0% 가정이다.

`breakEvenCustomers`에는 동일 통화의 실제 월 비용·고객당 순정산액·고객당 변동비를 넣는다.
기여이익이 0 이하이면 손익분기 고객 수를 산출하지 않는다. 저장은 매달 누적되므로 첫 달
손익만으로 영구 무료 보존의 지속 가능성을 판단하지 않는다.

## 4. 다음 구현과 운영 게이트

### 2026-09-05 로컬 압축 측정

```sh
# 모의 환경 source Vite 서버(4176) 실행 후, 명령에만 Node 22 적용
npx --yes --package=node@22 node scripts/operations/photo-benchmark.mjs
```

실제 `sanitizePhotoForUpload`를 Chromium에서 실행했다. 원격 요청은 차단하고 직접 생성한
합성 이미지 4개만 사용했다. EXIF 제거·회전 반영·중립 파일명·2048 상한·작은 원본 비확대를
검증했다. 이는 인물/피부/실제 사진의 시각 품질이나 iPhone 처리 성능, 인쇄 품질 증거가 아니다.

| 합성 입력 | 입력 KiB | 현재 2048 이하 KiB | 출력 픽셀 | 데스크톱 ms | 비교용 640 KiB | 비교용 2560 KiB |
|---|---:|---:|---|---:|---:|---:|
| 작은 원본 | 79.8 | 71.8 | 640×480 | 34.1 | 71.8 | 71.8 |
| 세부무늬 12MP | 7747.4 | 1607.3 | 2048×1536 | 160.9 | 155.7 | 2573.5 |
| 회전 EXIF 12MP | 3049.9 | 749.8 | 1536×2048 | 115.7 | 77.4 | 1165.0 |
| 투명 PNG | 1240.8 | 59.2 | 800×600 | 27.3 | 56.0 | 59.2 |

투명 영역은 흰색에 합성되고 alpha 채널이 없는 JPEG가 되는 것도 검사했다. 시간은 한 번의
로컬 실행값이며 동시 작업/기기에 따라 달라진다. p50/p95 또는 저사양 성능 수치가 아니다.

640/2560은 같은 JPEG quality로 별도 비교 인코딩한 값이지 업로드에 적용된 설정이 아니다.
비용 예시의 500/50KiB를 평균 실측값으로 채택하지 않는다. 디테일이 많으면 2048px도
1.5MiB를 넘는다. 현재 2048/.84를 유지하고, 목록용 작은 이미지와 실제 서비스의 콘텐츠를
포함하지 않는 bytes 집계로 다음 결정을 한다. 고객 파일의 일괄 재압축/덮어쓰기는 하지 않는다.

### 미완료 게이트

1. 위 benchmark를 지원 HEIC·대표 실제 사진·작은 iPhone까지 확장하고
   원본/최종 bytes, 픽셀, 소요 시간과 메모리를 확인한다. 합성 이미지 결과는 시각 품질 증거가 아니다.
2. 일반 media variant 아키텍처: 권한은 원본 record와 동일, 재시도는 동일 object id,
   한 variant 실패 시 부분 성공을 완료로 위장하지 않음. 기존 086–088 삭제 계약 보존.
3. Book Studio 담당과 정확한 선택·PPI·원본 재선택 계약을 연결. 서명 URL/사용자 원문을
   URL query나 로그로 전달하지 않음. 실제 export 소비 원장까지 연결되기 전 판매 OFF.
4. 출시 전 실제 plan/청구·Storage/egress/DB/Realtime peak, p95·오류율과 백업 복구 측정.
   100/1,000/10,000커플은 부하 시험 단계이며 현재 수용량 사실이 아님.
5. 비용 경보는 청구·오류 집계로 시작한다. 위치·건강·원문·사진·관계활동 감시를 analytics에
   추가하지 않는다. 원가 초과는 먼저 thumbnail/요청 중복/캐시/compute를 개선하고,
   고객 데이터 삭제나 프라이버시 유료화로 해결하지 않는다.

Production 변경: **NOT APPLIED**. 결제·새로운 수집·인쇄 보존 정책의 외부 활성화는 별도 게이트다.
