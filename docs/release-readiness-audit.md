# Release Readiness Audit (Phase A)

## 1. 정적 분석 및 빌드 환경 점검
- **제약 사항**: 현재 에이전트의 터미널 환경에서 `npm` 및 `git` 글로벌 명령어가 동작하지 않는 환경 제약이 존재합니다.
- **조치**: 코드와 마이그레이션 파일에 대한 수동 정적 분석(Manual Static Analysis)을 수행하여 P0 보안 취약점을 선별했습니다.

## 2. 코드 및 DB 보안(RLS) 점검 결과

### [Blocker] 커플 멤버 데이터 전역 유출
- **발견 내용**: `couple_members` 테이블에 무한 재귀 참조를 방지하기 위해 `USING (true)` 정책이 적용되어 누구나 전체 커플 관계를 조회할 수 있습니다.
- **해결 방안**: `get_my_active_couple_id()` SECURITY DEFINER 헬퍼 함수를 신설하여 RLS 없이 커플 ID를 조회한 뒤, 이를 바탕으로 RLS를 분리 적용했습니다. (005 마이그레이션 적용 완료)

### [Blocker] 커플 해제 트랜잭션 오류 (비대칭 해제)
- **발견 내용**: `disconnect_couple()` RPC가 호출한 본인의 상태만 `disconnected`로 변경하여, 상대방은 `active` 상태가 유지되는 비대칭 권한 결함이 있었습니다.
- **해결 방안**: RPC 내부 로직을 변경하여 동일 `couple_id`를 가진 모든 활성 멤버를 한 번에 업데이트하도록 트랜잭션 수정을 완료했습니다. (006 마이그레이션 적용 완료)

### [P0] 데이터 주입(Injection) 취약점
- **발견 내용**: `daily_records` INSERT 시 본인 `user_id`만 체크할 뿐, 소속된 `couple_id`인지 확인하지 않는 결함이 있었습니다.
- **해결 방안**: `WITH CHECK (couple_id = get_my_active_couple_id())` 제약을 추가하여 소속된 커플 외에는 데이터를 밀어넣을 수 없도록 방어했습니다. (005 마이그레이션 적용 완료)

### [P0] Storage 버킷 보안 미비
- **발견 내용**: `couple-media` 버킷을 생성하고 권한을 통제하는 마이그레이션 파일이 누락되어 있었습니다.
- **해결 방안**: `couple-media` 버킷을 생성하고, 객체의 `foldername`(=couple_id)을 기준으로 RLS를 적용하여 소속된 멤버만 업로드 및 조회가 가능하도록 격리했습니다. (007 마이그레이션 적용 완료)

### [P1] 민감 데이터 로컬스토리지 평문 캐싱
- **발견 내용**: PWA 오프라인 지원을 위해 `store.tsx`에서 전체 상태를 `localStorage`에 덤프할 때 비공개 기록(Private Records)의 본문까지 평문으로 저장되었습니다.
- **해결 방안**: 저장 전 직렬화 단계에서 `isPrivate`인 항목은 본문을 마스킹하고 첨부파일을 날린 상태로만 저장하며, 로그아웃 또는 연결 해제 시 캐시를 파기하도록 조치했습니다. (코드 수정 완료)

## 3. 권장 테스트 절차 (User Action Required)
> 본 환경에서 테스트가 불가능하므로, 아래 절차를 직접 수행해 주시기 바랍니다.

1. **DB 마이그레이션 반영**: 새로 추가된 005, 006, 007 마이그레이션을 Supabase에 적용합니다.
2. **TypeScript 빌드 테스트**: `npm run build`를 실행하여 린트/타입 에러가 없는지 확인합니다.
3. **PWA 로컬 스토리지 확인**: 앱 실행 후 개발자 도구 (F12) -> Application -> Local Storage 에서 비공개 기록의 본문이 마스킹 되어 저장되는지 확인합니다.
4. **커플 해제 테스트**: 한 기기에서 커플 해제를 진행했을 때 양측 모두 연결 대기 상태로 빠지는지 점검합니다.
